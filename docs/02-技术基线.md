## 2. 第三方依赖矩阵

| 依赖 | 用途 | 侧 | 策略 |
|---|---|---|---|
| Patchouli | 游戏内手册 | client | 软依赖：`mods.toml` 声明 `optional` + `CLIENT`，版本范围集中 `gradle.properties`；手册纯数据（`assets/strife/patchouli_books`），无库不加载、命令兜底。P0 只定边界，Java/入口物品接入留 P1；1.21.1 兼容性未复验（未验证） |
| Accessories（取代 Curios） | 法宝饰品槽 | both | **不引入硬依赖**（D-P0-1 自研极简槽）；仅可选兼容，P1 再评估 |
| JEI | 配方查看 | client | 软依赖：`mods.toml` 声明 `optional` + `CLIENT`，版本范围集中 `gradle.properties`；P0 无 Java 引用，P1 按标准 `RecipeInput` 协议接配方分类 |
| GeckoLib | 实体动画 | client | **M2 不引入**（D5）；预留 `AnimationProvider` 接口，M5 后可选接入 |

规则：
- 新增依赖 = ADR + 版本集中写入 `gradle.properties` 顶部，禁止散写；软依赖的 mods.toml 版本范围同样走 `gradle.properties` 占位符。
- 随包分发或必须存在的库走 `jar-jar` 嵌入或 `required`；软依赖一律 `optional`，禁止把软依赖类放上公共加载路径，禁止依赖 classpath 巧合。
- 接入软依赖 Java API 用 `ModList.get().isLoaded()` 隔离，禁止非安全路径直接引用软依赖类（防无库崩溃）；P0 边界阶段不引用其类，故暂无 `isLoaded` 调用。

### 2.1 软依赖接入边界（G-2 / D-P0-2，2026-10-25）

P0 只锁定边界与无库降级，不做全量接入。

| 库 | 当前已落 | 无库时 | P1 接入点（边界） |
|---|---|---|---|
| Patchouli | `mods.toml` optional + CLIENT；`assets/strife/patchouli_books/strife_compendium` 纯数据手册（book + 6 分类 + 28 条目）；`book.json` 已开 `creative_tab` | 手册不加载；游戏与全部命令不受影响 | 入口物品/API 调用只允许放 `com.strife.clientfx.compat.patchouli`；保持纯数据也能工作 |
| JEI | `mods.toml` optional + CLIENT；无 Java 引用 | 无配方页；`/strife recipe list\|show`、`/strife recipe artifact list\|show`、`/strife craft` 照常 | 插件类只允许放 `com.strife.clientfx.compat.jei`，按 `@JeiPlugin` 由 JEI 发现；配方用标准 `RecipeInput` 协议 |

守卫与降级验证：
- `SoftDependencyBoundaryTest` 解析 `mods.toml`，断言两者为 `optional`/`CLIENT` 且带非空版本范围。
- `SoftDependencyGuard` 扫描 `platform/src/main/java`，出现 `mezz.jei` 或 `vazkii.patchouli` 即失败；守卫用合成样本自测，源码根不存在时抛错而非静默通过。
- P1 首次接入须先在 ADR 记录并显式放行 `clientfx/compat/**`，守卫才允许引用——软依赖类不得出现在公共代码路径。
- 降级基线：本机测试与构建全程不加载 Patchouli/JEI；服务端 jar 不含 `clientfx`。实机"有库/无库"两态列入待验证台账 K 组。

## 3. 仓库与模块布局

单仓库（monorepo），Gradle 多模块：

```
<repo>/                        # 根目录 = 本机 clone 目标名，不承载 ID 语义（见下"路径说明"）
├── docs/                        # 本手册（唯一参照）
├── content/                     # 真相源：NUMBERS.md / STORY.md / JSON_SCHEMA.md / LORE.md
├── mod/                         # Gradle 根工程
│   ├── platform/                # 平台层：一个 MOD 制品，按包划分模块
│   │   └── src/main/java/com/strife/
│   │       ├── core/            # 注册、事件总线、附件、网络框架、命令框架
│   │       ├── realm/           # 境界/灵根/修为/打坐/突破/寿元
│   │       ├── combat/          # 功法/法术/法宝/妖兽 AI
│   │       ├── production/      # 统一配方机（丹/器/符/阵/种）
│   │       ├── quest/           # QuestEngine/对话树 DSL
│   │       ├── world/           # ambient_qi 场/矿石/宗门结构/上界维度
│   │       └── clientfx/        # 面板/轮盘/粒子/Patchouli（仅客户端加载）
│   ├── content-base/            # 内容层：纯 resources，无代码
│   │   └── src/main/resources/
│   │       ├── data/strife/    # strife_realms/ strife_techniques/ strife_spells/
│   │       │                    # strife_pills/ strife_artifacts/ strife_quests/
│   │       │                    # dialog_trees/ worldgen/ loot_table/ recipe/ advancement/
│   │       └── assets/strife/  # 贴图/模型/音效/lang(由生成器产出)
│   ├── tools/
│   │   ├── datagen/             # DataGen：NUMBERS.md/表格 → 游戏 JSON
│   │   └── validator/           # 构建期内容校验器（纯 JVM，不启动 MC）
│   └── buildSrc/                # 模块依赖图断言、发布任务
├── tables/                      # 策划表格（csv，DataGen 输入）
└── .github/workflows/           # CI（见 04 分册 §8）
```

要点：
- **平台层 = 一个 MOD 制品、包级模块化**；不做微服务式多 MOD 拆分（单人团队养不起跨制品版本矩阵），包边界靠 CI 依赖断言强制（03 §2）。
- **Java 包根统一 `com.strife.`（ADR-017），工具与构建代码不例外**：platform 用 `com.strife.<模块>`，tools 用 `com.strife.tools.<工具>`，buildSrc 用 `com.strife.conventions`（Gradle 插件 ID 仍为 `strife.conventions`，插件 ID 不是包名）。
- `content-base` 是纯资源模块，禁止出现 `src/main/java`；CI 由 `:content-base:checkImports` 检查，缺目录时也必须正常通过（缺目录 ≠ 违规）。
- clientfx 包只允许 `@OnlyIn` 语义下的客户端入口注册（用 NeoForge 分侧 ModEntrypoint），保证纯净 jar 可裁剪（03 §7）。

## 4. 环境搭建（新环境 30 分钟目标）

```bash
# 前置：JDK 21（temurin）、Git、IntelliJ IDEA Community（推荐）或 VSCode
git clone git@github.com:fusheng13145/Primordial-Strife.git "<repo>" && cd "<repo>/mod"
./gradlew --build-cache genSources     # 首次约 5–10 分钟
./gradlew :platform:runData            # 跑通 DataGen（M0 后）
./gradlew :platform:runClient          # 进游戏，聊天栏出现 strife 命令即成功
./gradlew :platform:runServer          # 纯净服务端验证（M0 准出项）
```

- **路径说明**：仓库根目录名 = 本机 clone 目标（当前 `Primordial Strife`，含空格），不是技术 ID——一切 ID/命名空间/产物名以 ADR-017 的 `strife` 为准。含空格路径对 Gradle 一般安全，但个别脚本/工具会踩坑，建议 clone 到无空格路径（如 `D:\work\strife`）；脚本引用根目录一律用带引号的 `"<repo>"`，禁止硬编码绝对路径。
- **Windows 硬约束：clone 路径必须纯 ASCII**（不得含中文等非 ASCII 目录名）。非 ASCII 路径 + 系统 ANSI 代码页（简体中文 Windows 默认 GBK/936）下，Gradle 以 UTF-8 写出 worker 的 classpath `@argfile`，JVM 启动器按平台 ANSI 编码读取 → 测试 worker 启动即 `ClassNotFoundException`，`./gradlew test` 全量失败（编译与 `java -cp` 直跑同一路径均正常，可据此判定）。上游缺陷：gradle/gradle #30304（修复进 9.7.0）、#30391（未修复）。此时**不得**改 `systemProperty`/`jvmArgs` 或跳过测试掩盖，结论是换路径不是换代码。
- Gradle daemon + build cache 常开；CI 与本地共用同一份 `gradle.properties` 内存参数。
- Windows 统一用 Git Bash 执行脚本，仓库内脚本禁止 PowerShell 专有语法。
- **`runServer` 前需自备 `mod/platform/run/server/eula.txt`（内容 `eula=true`）**：该目录不入库，首次运行不自动同意，否则服务端启动即退出；同意 Mojang EULA 属个人操作，由本人确认。
- **`runClient` 首屏日志可能出现 `authlib ... Read timed out`**（session/realms 域名受限）：仅账号会话检查，不影响 MOD 载入与主菜单。判定"载入成功"以这三行为准——mod 列表出现 `Primordial Strife x.y.z (strife)`、`strife platform entry constructed`、`ResourceManager: ... mod/strife ...`。

### 4.1 两种启动方式：开发启动 vs 正式启动器

| | 开发启动（`runClient`/`runServer`） | 正式启动器（官方启动器 / PCL2 / HMCL） |
|---|---|---|
| 用途 | 写代码、断点、改包重编的唯一途径 | 只玩、验收、给测试者发测试包 |
| 前置 | 本仓库 + JDK 21，Gradle 拉起 NeoForge 开发客户端 | 装一个 **NeoForge 1.21.1** 实例（版本号须与 `gradle.properties` 的 `neoforge_version` 一致），把 `mod/platform/build/libs/strife-0.0.1.jar` 放进该实例 `mods/` |
| 存档位置 | `mod/platform/run/`（不入库） | 启动器自己的 `.minecraft/saves` |
| 账号 | 离线开发账号（不登录） | 启动器的正式登录账号 |
| 改代码后 | 重跑任务即生效 | 须重新 `./gradlew :platform:build` 并替换 `mods/` 里的 jar |

要点：
- **两条独立路径，互不依赖**：`runClient` 不依赖本机装官方启动器，正式启动器也从不读 `mod/platform/run/`。
- 制品是**普通 NeoForge MOD jar**（`neoforge.mods.toml` 声明依赖 `neoforge [21.1.251,)`、`minecraft [1.21.1,)`），任何能装 NeoForge 1.21.1 实例的启动器都可用；PCL2/HMCL 需在"版本"里选 NeoForge 而非 Forge——**装错加载器类型会直接不显示本 MOD**（未验证：官方启动器实机安装截至本文未在真机走过一遍，仅由 jar 内清单与依赖声明推断）。
- 走启动器时两条制品都在：`./gradlew :platform:build` 出主 jar，`./gradlew :platform:serverJar` 出服务端 jar（`clientfx` 已落地：客户端 HUD + 修炼面板 + 对话 UI，`dist=CLIENT` 分侧入口 + serverJar 整包剔除 `com/strife/clientfx/**`；CI 每次用它无头开服 60s 冒烟，03 §7）。content-base 产物已真实进 jar（**135 个内容产物 + 2 份 lang + 43 张物品贴图 + 52 份物品模型 + 9 份方块模型/blockstate**，`checkContentBundled` 把守）。游戏内可见物：单机左下角修仙 HUD（境界/修为/寿元/灵根）、K 键修炼面板、落霞山麓附近自动摆出的三名 NPC（`tables/npcs.csv` 驱动）与 `/strife npc spawn <npc_id>` 手动补位、右键开对话树、`/strife info`，详见根目录 `SETUP.md`。

### 4.2 三条验证通道（按用途选，勿混用）

| 通道 | 命令 | 用途 | 判据 |
|---|---|---|---|
| **1 开发客户端** | `./gradlew :platform:runClient` | 日常改代码后的端到端验证（渲染、UI、实体、进世界） | §4 三行载入判据；进世界后 `latest.log` 无 ERROR |
| **2 纯 ASCII worktree** | `git worktree add C:/strife-test <branch>` → `cd C:/strife-test/mod && ./gradlew test` | **Windows 中文路径下唯一能跑单测的通道**（§4 GBK 缺陷） | 逐模块用例计数（platform ≥1 / buildSrc ≥1 / validator ≥1 / datagen ≥1） |
| **3 正式启动器** | `./gradlew :platform:build` → jar 丢进 NeoForge 1.21.1 实例 `mods/` | 交付验收、测试者试玩；**PCL2 / HMCL / 官方启动器均可** | 游戏内可见物同 §4.1；`latest.log` 无 ERROR |

- 通道 3 实例版本号须与 `gradle.properties` 的 `neoforge_version` 兼容（本仓当前锁定 21.1.251，向上兼容补丁号）；**装错加载器类型（Forge 而非 NeoForge）会直接不显示本 MOD**。
- 通道 2 的 worktree 是独立检出：**必须在目标 commit 上跑**，否则测旧代码；测完 `git worktree remove` 清理。
- 交单门禁（06 §4）要求四者全绿：格式 + 编译 + 单测 + validator；通道 1/3 不能替代单测。

## 5. 代码规范（对本人和 Agent 同等生效）

| 项 | 规范 |
|---|---|
| 语言级别 | Java 21；鼓励 record / sealed / pattern matching |
| 风格 | Google Java Style 变体：4 空格缩进、120 列；Spotless 格式化，`./gradlew spotlessCheck` 进 CI |
| 静态检查 | Error Prone（或 Checkstyle 简化集）；新代码不得新增抑制注释，存量抑制须挂 issue 号 |
| 命名 | 类/方法英文；内容 ID 全小写下划线（04 分册 §4）；禁止拼音缩写混入代码命名 |
| 魔法数字 | 禁止；数值一律查表或从 DataGen 产物读取，违规由本人复核拦截 |
| 注释 | 默认不写；只写"为什么"，引用 ADR/issue 编号 |
| 异常 | 服务端逻辑禁止吞异常；内容加载失败必须 fail-fast 并报出具体 JSON 路径 |
| 日志 | 统一 `Logger`（命名空间前缀 `strife/<module>`）；tick 热路径禁止 info 级以上日志 |
| 提交 | Conventional Commits（`feat(realm): ...`）；一个小提交一件事，禁止万行式"AI 大改动"提交 |
| 分支 | `leyon`（日常集成，Agent 提交先推这里）→ PR → `main`（受保护，**仅本人批准后合入**）；`beta/X.Y`（M6 起）；单工单可在 `agent/<任务号>-<slug>` 做未验证实验，交付一律并进 `leyon` |

## 6. 存档兼容基线

- 玩家数据全部走 NeoForge **Attachments**（`AttachmentType` 注册于 core），世界级数据走 saved data / 区块 NBT。
- 新增字段必须带默认值；删除字段保留 reader 兼容一个主版本；**破坏性变更 = 数据大版本号 +1，且必须 ADR**。
- 每次改数据结构的 PR 必须附带"重载存档三次一致"的手工用例结论（07 分册准出条件）。
