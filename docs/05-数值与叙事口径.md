# 05 数值与叙事口径

## 1. NUMBERS.md：全部数值的唯一真相源

- 位置：`content/NUMBERS.md`。格式：带约定标题的结构化 Markdown + 内嵌 YAML 块，DataGen 解析（解析失败 = 构建失败）。
- 收录范围：境界链（qi_max/lifespan/unlocks）、突破/渡劫成功率、打坐基础速率与打断惩罚比例、灵根系数表、成长比校验区间、丹药加成、寿元结算、伤害公式表、冷却/消耗、掉落概率、限速参数。
- **代码里出现任何 §1 收录范围内的字面量即 Review 驳回**。运行时数值全部来自 DataGen 产物查表。
- **配置口径**：模组 config 只放行为开关与性能档位（如日志级别、同步频率上限）；凡玩家成长/战斗/经济可感知的数值（速率、概率、伤害、限速阈值等）一律属 NUMBERS.md 管辖、经 DataGen 进表，**禁止做成 config 数值项**造成第二数值真相源。
- 调参流程：改 NUMBERS.md → 跑 DataGen + Validator（越界/成长比检查）→ 蒙特卡洛抽样 → 提交。外部表格便于非程序成员与 Agent 调参。

## 2. 核心公式（口径锁定）

```
实际修炼速率 = 基础速率(查表) × 灵根系数 × 环境系数(AmbientQi) × 功法倍率 × (1 + 丹药加成)
```

- 四项系数全部来自表；任一系数为 0 必须有可展示的 tooltip 解释（"灵根不适配"）。
- 伤害：`damage = formula_key 查表(base, 境界系数, 功法加成, 穿透)`，禁止公式旁路。
- 相邻境界总成长比约束在 **1.8–2.5**，Validator 硬校验（防数值崩盘风险 R3）。

## 3. 境界链（M0 骨架表基线）

凡人 → 练气(1–9层) → 筑基(初/中/后/圆满) → 金丹 → 元婴 → 化神 → [后续三段：暂定 炼虚 → 合体 → 渡劫/飞升，占位命名，随 STORY.md 定稿]。

- 每境界必填：qi_max、lifespan、unlocks（功能/内容清单）、breakthrough_success_key。
- 示例锚点（初版，NUMBERS.md 定稿前视为草案）：练气→筑基 90%，筑基→金丹 85%，金丹→元婴 75%→70%（失败每次 -5%，下限 40%）。
- **O1 拍板**：NUMBERS.md 骨架表（全链条 + 上述必填字段 + 锚点值）为 M0 准出物，由数值角色 + Agent 产出、组长审定；此后所有数值变更走表格流程，不走聊天。

## 4. 突破失败与大限（O4/D6 已拍板）

| 事件 | 代价（非破坏性） |
|---|---|
| 突破失败 | 修为回退至上限的 60%–80%（查表）；本次投入的突破辅助材料损耗；不扣境界、不损寿元、不掉物品栏 |
| 渡劫失败 | 同上加"重伤"虚弱状态（全属性 -30%，限时），天劫材料散落于劫台附近可拾回 |
| 寿元尽（大限） | 修为回退一档境界下限 + 虚弱 + 寿元重置为"残余寿元"（小值）；提供明确的续命玩法路径（丹药/任务），绝不删角色 |

设计原则：代价可感知、可恢复、可预期（面板显示失败后果）。

## 5. 修为获取渠道（O3/D7 已拍板）

锁定三种：**打坐（主渠道）、丹药（加成）、任务奖励（节点性）**。灵石购买修为、挂机收益之类一律不做。新增渠道 = 改 NUMBERS.md 渠道表 + ADR + 面板来源明细同步。

## 6. STORY.md：世界观与章节大纲

- 位置：`content/STORY.md`。结构：世界观总纲 → 各章主题/场景/关键 NPC/情感曲线 → 任务节点骨架（与 quest DAG 表通过 `ch<N>_` ID 前缀互相引用）。
- **O2 拍板**：序章大纲由剧情角色 + Agent 于 M2 末产出、M3 前定稿冻结；第一章允许 M3 期间滚动定稿，但节点骨架必须先冻结再填对话文本。
- 主题基调：**「玄黄劫争」——万族争劫、大道并立**。世界有自己的大势（宗门对立、人妖之战、外敌入侵等主线级事变），玩家可入宗门、可行散修之道，在事变中择路而非旁观；叙事重心是"个人求道与世界洪流的相互作用"（H2 身份/H3 因果/H7 战争钩子即为其工程表达）。边界不变：**不做 MMO 化系统**（无玩家间经济、无跨服、无 PvP 平衡体系）——势力对抗是模拟出来的世界内容，不是竞技场（对齐 01 分册不做清单）。

## 7. AI 文本生产流程（D2）

```
STORY.md 节点骨架 → Agent 起草对话/条目文本（附上下文包：世界观卡 + 前文 + 目标情绪）
→ 人工润色（native zh_cn 语感）→ 入 tables/dialog_trees 与 lang 源表 → DataGen + Validator → 抽查回放
```

- 每节点首版允许骨架文本（2–3 句），玩法优先（风险 R2 应对）；情感关键节点（序章突破、章节首领告别等）必须人工重写。
- Agent 产文必须同时提交：文本 + 变体 2 个 + 用到的设定引用清单（防吃书）。
- **一致性防线**：`content/LORE.md`（设定卡，随 STORY.md 维护）是所有 Agent 文本任务的强制上下文输入；与 LORE 冲突的文本在人工审核阶段驳回。
- **版权红线**：09 分册与调研报告中的网文专名（"韩立式""荒古圣体"等）与情节**仅限内部调研用语，一律不得进入游戏内文本/资产命名**；对外内容须为自研设定（LORE.md 卡内），人工审核含"致敬相似性自检"一项。

## 8. 本地化节奏（O5/D4 已拍板）

zh_cn 为源语言，key 全覆盖是硬门禁；en_us 在 M5 前由 Agent 批量翻译占位过 CI（允许机翻低优先级），M5 起随平衡迭代逐章精修，Beta 前完成序章 + 第一章。

## 9. 动画与表现范围（O6/D5 已拍板）

M2 战斗表现 = 原版弹道 + 粒子 + 音效（AI 生成短音效）。GeckoLib 至多用于 1–2 个高规格 Boss/妖兽，接入与否在 M4 末评审；`AnimationProvider` 接口保证"无动画也完全可玩"。

## 10. 联机优先级（O7/D3 已拍板）

单人优先。服务端权威 + 幂等 + 限速从 M0 就按 03 分册执行（这是架构，不是功能），但**多人功能加固（同屏性能、多人任务协作、反滥用调优）于 M5 启动**（M0–M4 不做，与 01 D3 同口径）；Beta 明确标注"联机为实验性"。
