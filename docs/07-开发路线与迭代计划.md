# 07 开发路线与迭代计划

> 本册定义**单人独立开发**的工作模式、阶段划分与后续全量路线。历史里程碑保留 M0–M5 编号，现行阶段统一用 P0–P6。
>
> 路线是**计划不是承诺**：每阶段启动时按当时代码与证据重估，量级只用于排批次；准出条件才是合同（§2）。

## 1. 工作模式：单人 + AI Agent

| 角色 | 职责 | 边界 |
|---|---|---|
| **本人** | 唯一决策者、实现者、审核者、真相源确认人、发布负责人 | core/realm 由本人写；ADR、破档、门禁变更由本人拍板 |
| **AI Agent** | 探索、起草、实现灰区/开区改动、写测试、填表、生成文本与占位资产、跑验证、整理文档 | 产出默认"未验收"；不得自批、不得改门禁让它变绿、不得代本人确认真相源 |

规则：一个批次只推进 1 条主线 + 至多 1 条内容/文档线（并发是返工主要来源）；Agent 产出必须过 §8.3 四道复核才可交付；决策只认 ADR、手册与真相源，聊天记录、口头约定、Agent 的"我记得"不算依据；历史文档中的 A/B/C/D 为已废止称谓，统一理解为"本人"（ADR-024）。

## 2. 推进原则

- **准出条件合同**：每阶段只锁准出条件，不锁功能清单细节；准出条件不因进度压力降级。
- **批次制**：1 批 ≈ 1 个有效工作日，每批必须有可复现证据（命令输出、测试报告、截图/日志、提交哈希）。
- **WIP 上限**：并行主线 ≤1，内容/文档线 ≤1，未合并实验分支 ≤1。
- **砍范围顺序**：世界系统 → 表现 → 支线内容；**主链、内容管线、realm 永不砍**。
- **新增系统必须 ADR**：09 图谱是地图不是待办；图谱外临时发明一律拒绝。
- **每批收尾**：更新 [`10-当前进展与交接.md`](10-当前进展与交接.md) 快照与 [`../deliverables/待验证台账.md`](../deliverables/待验证台账.md)；未验证项写"未验证"，不得写"已完成"。
- **证据口径**：结论必须挂可重生成命令或可复核记录；凭印象写数字视为缺陷（R9/R12）。

**目标**：序章 + 第一章完整可玩，达到对外发布候选质量；玩法、内容、表现、稳定性四条线同时收口。

4. **世界表现**：宗门厅堂形态（LORE 定稿）、上界至少 1 个可探索点、灵气浓度场观感调优。
5. **手册与引导（D12）**：自研入门指引物为主载体（覆盖境界/修炼/战斗/生产/任务五域），Patchouli/JEI 仅作增强；无手册时命令必须能完成所有操作。
6. **本地化**：en_us 全量占位过 CI，序章 + 第一章精修；zh_cn 全量终审。
7. **稳定性与发布**：2h 连续运行、内存增长 <200MB、tick 预算；占位资产清点清零或挂账；三制品 + changelog 与安装说明。

## 8. 单人工作节奏与并发控制

### 8.1 日批次模板

1. **开工**：从 P 阶段工单池取 1 条主线；写清验收命令与证据路径。
2. **红先**：行为改动先写失败测试；没有红脸就不写实现。
3. **实现**：只动工单范围内文件；超范围重构另开工单。
4. **门禁**：`spotlessCheck build test validator`；Windows 中文路径下测试走 ASCII worktree。
5. **收尾**：更新 10 册快照与待验证台账；记录未验证项；提交按 Conventional Commits。

### 8.2 WIP 与分支

同时只开 1 条代码主线 + 1 条内容/文档线，第三条排队；未合并实验分支 ≤1，超过说明在并行逃避收口。分支：`leyon` 日常集成，`agent/<任务号>-<slug>` 只做未验证实验，失败即丢弃不带入交付。大改动先写 ADR 草案再动代码；破档改动必须单独批次。

### 8.3 独立复核四道防线（替代第二个人类）

1. **红先测试**：每个行为改动先看失败再写实现；测试失败原因必须是功能缺失，不是编译错误。
2. **全新上下文复核**：高风险改动（core/realm、公共契约、破档、门禁）派**无实现上下文**的 Agent 只读复核 diff 与规格，专找"假绿、越界、未验证断言"。
3. **外部门禁**：CI + Validator + 模块依赖断言 + 纯净 jar 冒烟；门禁红就是红，不许改门禁。
4. **实机证据**：涉及游戏内行为的改动必须有本人实机记录；Agent 不得自证。

> 复核结论写进 PR 描述或 10 册；"我看过了"不算证据。

### 8.4 决策与文档同步

系统级取舍先写 ADR（08 册），拍板后 24 小时内同步到对应分册正文。真相源变更：先改 `content/`，再跑 DataGen + Validator，最后同步 10 册；不允许"根据代码反推真相源"。文档引用使用章节锚点或提交哈希，不写易漂行号；跨分册引用写"分册号 + 小节标题"。

### 8.5 停线规则

出现任一情况，停止当前批次并先修复：门禁红且原因未定位；真相源与产物冲突；第三方 API 行为无出处（未验证）；Agent 产出假绿测试、越权重构或删除断言；同一缺陷连续两次修复失败（转 systematic-debugging，不再猜）。

### 8.6 进度口径

进度只按**准出条件**和**证据**报，不按百分比感觉报；每阶段结束给三行：已达成（证据）、未达成（原因）、下一阶段入口条件。对外承诺只用 W4 演练实测的"新增一章耗时"，不用规划批次换算。
