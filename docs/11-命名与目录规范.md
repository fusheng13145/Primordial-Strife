## 1. 一条不可让步的红线

> **机器标识符用 ASCII 拼音，人类可读文本用中文。两者一一对应，映射只允许出现在 lang 文件与 CSV 的显示列里。**

这条红线不能因为"看起来更整齐"而破例。理由是**物理约束**，不是偏好：

| 约束 | 事实 | 后果 |
|---|---|---|
| Minecraft 资源 ID 只允许 `[a-z0-9_.]` | `ResourceLocation` 的字符白名单是原版硬校验 | 物品/方块/实体 ID 写成 `灵玉矿` 会**加载期直接崩** |
| 1.21.1 掉落表路径由注册名推导 | `BlockBehaviour` 用 `withPrefix("blocks/")` 从 `ResourceLocation` 推出 | ID 与掉落表路径是**同一条约束**，改 ID 就得同步改表 |
| Java 标识符可含 Unicode 但不可含 `-` | `package com.strife.战斗` 合法但**不可用** | 反过来：`client-fx` 这种带连字符的目录名在 Java 里非法 |
| CSV 表头是列契约 | `JSON_SCHEMA.md` 锁死列名 | 改列名 = 破档（04 §5） |

**所以"全部中文"在本项目的准确含义是**：游戏内玩家看到的每一个字都是中文（境界名、物品名、法术名、NPC 对白、GUI 文案、提示消息），而承载这些文字的 ID 保持拼音。阁下若要求把 ID 也改成中文，那需要先推翻原版 `ResourceLocation` 的白名单——这属于"改游戏本体"，不在本项目可动范围内。

## 2. 五类命名的分区规则

| 类别 | 规则 | 语言 | 例 |
|---|---|---|---|
| **资源 ID**（注册名、lang key、产物文件名、CSV `id` 列） | `[a-z][a-z0-9_]*`，全小写，下划线分词，**不得含连字符与驼峰** | 拼音 | `block_ore_lingyu`、`pill_juqi` |
| **类名 / 包名** | Java 惯例：`UpperCamelCase` / 全小写无下划线，根包 `com.strife`（ADR-017） | 英文 | `OreTables`、`com.strife.world` |
| **玩家可见文本** | 简体中文；专有名词用设定表（`content/LORE.md`）里的定名 | **中文** | 「灵玉矿」「火弹术」「凡人」 |
| **文档文件** | `NN-中文标题.md`，两位数字前缀维持排序 | **中文** | `10-当前进展与交接.md` |
| **配置 / 脚本** | 与被约束对象同名；Gradle 模块名全小写 | 英文 | `mod/settings.gradle` 里 `include 'content-base'` |

### 2.1 lang key 的构造

格式固定为 `<类别>.<命名空间>.<id>`，与 Minecraft 原版约定一致：

```
realm.strife.qili                    → "练气"
item.strife.pill_juqi                → "聚气丹"
block.strife.block_ore_lingyu        → "灵玉矿"
msg.strife.sit.start                 → "入定——气机流转。"
gui.strife.panel.title               → "修仙面板"
gui.strife.hud.realm                 → "境界 %s"      ← id 段可再点分
gui.strife.panel.affiliation.none    → "散修"          ← 分组.分组.叶子
```

- 类别前缀现役 12 个：`realm` `faction` `technique` `spell` `item` `block` `entity` `effect` `element` `gui` `msg` `key`
- **id 段允许点分多级**（`gui`/`msg` 天然带二级分组），但每段仍须 `[a-z][a-z0-9_]*`——这条由 V-NAME 机器把关
- **新增类别**必须先在 `JSON_SCHEMA.md` 登记，再进 lang；`V-TEXT` 门禁守 zh_cn/en_us key 双向对齐
- 类别名用**单数名词**（`item` 不是 `items`），与原版 `item.strife.*` 一致

### 2.2 显示名（中文）从哪来

中文名**只允许**出现在三个地方，别的地方都是漂移源：

1. `assets/strife/lang/zh_cn.json` 的**值**——游戏内显示的唯一来源
2. `tables/*.csv` 的**显示列**与 `_note` 注释列——给内容作者看，不进产物
3. `content/` 四份真相源——设定定名的来源

**禁止**：在 Java 里硬编码中文界面文案当"临时方案"。查证方式：面向玩家的字符串必须走 `Component.translatable("...".strife.xxx")`，让 V-TEXT 能守覆盖率。当前 `OreCommand` 的 `[OK]`/`[缺]` 标记属**调试输出**（运维判据，非玩家 UI），豁免但已在 `docs/10` 记录。

### 2.3 拼音的取名规则

ID 用拼音时按**读音**取，不按字面：

| 中文 | 拼音 ID | 说明 |
|---|---|---|
| 灵玉矿 | `lingyu` | 正读 |
| 赤炎矿 | `chiyan` | 正读，不写 `chi_yan` |
| 寒玉矿 | `hanyu` | 正读 |
| 聚气丹 | `juqi` | 正读 |
| 青石观 | `qingshi` | 正读 |
| 筑基层（境界） | `zhuji` | 正读（注意与"筑基"同音不同字，靠 `realm.` 类别区分） |

规则：
- **单字/双字词不拆**，双字连写（`juqi` 不是 `ju_qi`）
- 多语义用**下划线**分隔（`ore_lingyu` 是"矿石·灵玉"，不是"灵玉矿石"）
- 避免多音字歧义时，在 `content/LORE.md` 的术语表里登记读音

## 3. 目录结构约定

```
Primordial Strife/                    ← 仓库根 = 文档 + 真相源 + 工程
├── docs/                             手册（唯一参照）
│   ├── NN-中文标题.md                 分册，数字前缀排序
│   └── appendix/                      草案与调研（非规范）
├── content/                          真相源（NUMBERS/STORY/LORE/JSON_SCHEMA）
├── tables/                           策划填表区（CSV 唯一入口）
├── mod/                              ← Gradle 根（不是仓库根！）
│   ├── platform/                     主模块：combat/quest/world/realm/production/core + client_fx
│   ├── content-base/                 资源与 DataGen 产物
│   ├── tools/datagen/                产物生成器
│   ├── tools/validator/              11 项门禁
│   └── buildSrc/                     构建逻辑
└── .github/                          CI 与脚本
```

约定：

- **Gradle 根在 `mod/`**，在仓库根跑 `./gradlew` 会报 "does not contain a Gradle build"
- 模块名全小写；多词用连字符（`content-base`）——Gradle 模块名不是 Java 包，允许连字符
- **Java 包名一律不用下划线**（ADR-017 根包 `com.strife`）
- 产物目录用 `snake_case`，且必须由 DataGen 生成并与源表同提交（V-FRESH 守漂移）

### 3.1 生成物与缓存不进版本库

以下目录由构建产生，`.gitignore` 已覆盖，**不应出现在任何提交里**：

```
/mod/build/           /mod/*/build/        /mod/*/run/        .gradle/
```

`mod/platform/run/` 是 `runClient`/`runServer` 的工作目录（含 `config/`、`server.properties`、日志），**保留是有意的**——下次跑通道 C 复用；但它不是交付物，交付只认 `mod/platform/build/libs/*.jar`。

## 4. 已知偏离（待裁决，不擅自改）

诚实记录，不静默"顺手修掉"——改这些会波及 CI 门禁与多层文档，属破档级：

| 项 | 现状 | 应为 | 影响面 | 处置 |
|---|---|---|---|---|
| `client_fx` 包名 | 下划线 | `clientfx` | `ModuleDependencyRules` 断言、`docs/03` §分层、ClientDataBridge 等 8 个类的 import | **提请 A 裁决**：新模块一律不用下划线；是否回改存量走 ADR |
| `content/NUMBERS.md` 等真相源 | 大写文件名 | 小写 | Validator 与 DataGen 按固定路径读取 | 与 04 §5 契约绑定，改名即破档，**保持现状** |
| `docs/06-AI协作规范.md` | 含连字符 | `06-*.md` | 无（纯文档） | 下次重写该分册时顺手改，当前不动以免破档引用 |

## 5. 新增内容的命名自检清单

提交前逐条过：

- [ ] 资源 ID 全小写、下划线分词、无连字符、无驼峰
- [ ] lang key 类别前缀已在 `JSON_SCHEMA.md` 登记
- [ ] zh_cn 与 en_us **都**加了 key，zh_cn 值是中文，en_us 值非空串
- [ ] 中文显示名只在 lang / CSV 显示列 / `content/` 三处出现
- [ ] 面向玩家的文案走 `Component.translatable`，无硬编码中文
- [ ] DataGen 产物与源表**同一个提交**
- [ ] 新建目录有归属说明，不落在 `mod/build/` 等生成物区
- [ ] `gradle :tools:validator:run` → `problems=0`
- [ ] `gradle spotlessCheck` → 绿
