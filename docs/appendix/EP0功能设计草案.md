## 1. 境界面板（realm / client_fx）

**玩家视角**：`V`（默认键，config 开关）打开"自身"面板：境界名 + 第几段、修为条（`qi / qi_max`）、寿元剩余（"四十一年"式，不显示刻）、四项修炼系数明细（基础 × 灵根 × 环境 × 功法 ×(1+丹)）、已解锁清单、被置灰的功法及原因。

**服务端权威点**：面板所有数字来自 S2C 同步的 `StrifeData` + 内容表；客户端**不本地推算**修为（03 §4）。系数明细由服务端算好下发（含每项 tooltip 的解释键），避免两端不一致。

**表依赖**：`realm:<id>:*`、`sr:*`、`sit:*`、`world:ambient_qi_min/max`、`techniques:qi_rate_ratio`、`pill:*`。

**预算与红线**：面板刷新走独立 sync channel，静止时单玩家 ≤5 包/s（03 §6 `[锚]`）；面板打开不产生额外查表 IO，境界表在内容加载时建索引。

**手工用例**
1. 新号进服 → 面板显示凡人、`qi_max` 与表一致、系数四项可见且乘积 = 显示速率。
2. 洗髓道具重置灵根后，不满足 `required_spiritroot` 的已学功法置灰 + 显示 `disabled_by` 文案（禁止静默失效，03 §8）。
3. 断线重连 → 面板数值与服务端日志一致（时间片结算，03 §6 末）。

## 2. 打坐（realm）

**流程**：按住键/命令进入入定 → 角色盘坐 + 粒子（客户端表现）→ 每次结算弹"修为 +N"浮字（可关）→ 受击/移动/被推送打断。

**权威点**：起止状态机（`idle → sitting → breakthrough → dead`）在服务端；打坐意图包限速 `rl:sit_per_sec`。结算用**时间片**：记录起止时间戳 + 环境快照（区域 `ambient_qi_ratio`、当时功法与丹药），断线重连补算（03 §6 `[锚]`）。

**表依赖**：`realm:<id>:sit_rate`、`sit:tick_interval_ticks`、`sit:interrupt_progress_keep`、`sit:interrupt_cooldown_sec`、`rl:sit_per_sec`。

**预算**：单玩家附加逻辑 ≤0.05ms/tick，靠降频分桶（每 `tick_interval_ticks` 一次），**不每 tick 计算**（03 §6 `[锚]`）。

**用例**：① 打断保留比例正确（面板"已积累 × keep"可见）；② 打断后冷却内再次入定被拒且给出原因；③ 挂机 20 分钟修为 = 同时长手动打坐（流速一致，`life:years_per_*`）；④ 离线不产出。

## 3. 突破与渡劫（realm）

**流程**：修为达上限 + 条件满足（材料/任务 flag）→ 面板出现"突破"按钮 → 选劫台（渡劫时）→ 确认页显示：本次成功率（`base + fail_step × attempts`）、失败回退区间、将损耗的材料 → 结算 → 结果广播（渡劫）。

**权威点**：成功率查表 + 服务端 RNG；`attempts` 入档（`StrifeData.breakthroughAttempts`）；请求限速 `rl:breakthrough_per_min` 防连点刷修正；客户端**不得**携带任何结果字段。

**表依赖**：`bs:<key>`、`bt_cost:*`、`realm:<id>:breakthrough_success_key`、quests 的 `conditions`（材料/flag）。

**预算与红线**：渡劫实体与伤害全服务端（03 §8）；同屏法术实体 ≤64 与对象池适用于天劫雷柱。

**用例**：① 失败只回退修为到 60–80%（区间内），境界不降、物品栏不损（D6 `[锚]`）；② 连点 10 次只按限速处理；③ 渡劫失败进入 `combat:tribulation_debuff_key` 且时长 = `bt_cost:debuff_duration_sec`；④ 天劫材料在 `bt_cost:tribulation_drop_radius` 内可拾回。

## 4. 寿元与大限（realm）

**流程**：寿元随现实时间流逝（与打坐同流速）；剩余为 0 → 大限结算：修为退一档下限 + `life:dasheng_debuff_key` 虚弱 + 寿元重置为 `lifespan_years × dasheng_reset_years_ratio`；面板红字提示续命路径（`life:limit_recovery_pill_key`）。

**权威点**：全部服务端计算；不删角色、不掉存档级资产（D6 `[锚]`）。

**表依赖**：`realm:<id>:lifespan_years`、`life:*`。

**用例**：① `/strife lifespan set 1`（测试命令，M1）后 60 秒内触发大限，数值与表一致；② 虚弱期间四项系数明细可见负项来源；③ 大限后任务进度与附件其余字段不变。

## 5. 灵根（realm）

**流程**：首次进服服务端生成（seeded by 玩家 UUID + 世界 seed，永不重算）→ 面板显示五行 + 品阶 + 一句话解释（"五行皆杂，进气慢"）。

**权威点**：生成与存储全服务端；`spiritrootQuality` / `spiritrootElements` 为 ordinal + 位掩码（`StrifeData`），显示层由 client_fx 查表渲染。

**表依赖**：`sr:quality_tier_*`、`sr:roll_weights`、`sr:affinity_*`；相生相克映射见 LORE §2.1（待 C 确认后进 NUMBERS）。

**用例**：① 同 UUID 同世界 seed 重开存档 → 灵根不变；② 换世界 seed → 允许不同（记录到台账）；③ 洗髓后旧功法置灰链路（同 §1 用例 2）。

## 6. 功法（combat / realm 交界）

**流程**：获得（任务奖励 / 传承 / 后续商店）→ 装备一件主修功法 → 影响 `qi_rate_ratio` 与可用法术；`required_realm` / `required_spiritroot` 不满足则整卡置灰并写明原因。

**权威点**：装备与切换服务端校验；倍率参与速率计算（服务端）。

**表依赖**：`strife_techniques` 全字段（JSON_SCHEMA §4.2）。

**用例**：① 境界不足时装备被拒且有具体原因；② 洗髓致灰；③ 面板速率随功法切换即时变化且 = 四项乘积。

## 7. 法术（combat）

**流程**：轮盘（默认 `R`，client_fx）选已习得法术 → 目标/方向 → 施法。冷却与灵气余额在轮盘上以灰显 + 倒计时呈现，但**判定在服务端**。

**权威点**：冷却、余额、境界/功法前置、目标距离四项必查（03 §4 `[锚]`）；意图包限速 `rl:cast_per_sec`；同屏实体上限与超距回收。

**表依赖**：`strife_spells`（projectile/cost/cooldown/damage_formula_key）、`combat:*`。

**用例**：① 余额不足时客户端可点、服务端拒绝并回明确原因码；② 端到端延迟 <100ms（本地联机，03 §6 `[锚]`，性能基准在 M2 接 CI）；③ 超 64 实体时新施法被拒绝且不报错。

## 8. 法宝（combat / production 交界）

**流程**：器图炼制 → 入槽（`slot_type`）→ 主动技能走 `active_skill`，被动走 `passives`；耐久消耗与修复回 production。

**权威点**：冷却、耐久、装备槽校验（03 §4 `[锚]`）。

**表依赖**：`strife_artifacts`、`combat:artifact_cooldown_sec`、`rl:artifact_per_sec`。

**用例**：① 耐久为 0 时主动技能拒绝；② 换槽旧法宝效果即时移除（无残留 buff）；③ 品质概率分布抽查靠蒙特卡洛 10 万次（04 §8 每晚任务，M2 起）。

## 9. 炼丹（production，统一配方机）

**流程**：开炉 → 3×3 投料（`pattern` DSL）→ 火候窗口小游戏（0–1 连续量，落在 `heat_range` 内维持时长）→ 出丹（`outputs` 概率）。

**权威点**：投料合法性、火候曲线、结果全部服务端；物品真实存在与扣除走服务端清单。

**表依赖**：`strife_pills`、`pill:*`、`world:ore_drop_weights`（材料侧）。

**用例**：① 同一输入同结果（RNG 以玩家 + 会话 seed 派生，可复现）；② 概率和 ≠1 的表构建失败（`V-PROB`）；③ 废丹进 `failure_output`；④ 加成生效在打坐速率且面板可见来源。

## 10. 炼器（production）

**流程**：器胚 + 核心材料 + 禁制数 → 品质抽签 → 成品；禁制数决定后续温养/开光线（EP1 才玩法化）。

**表依赖**：`strife_artifacts`；`quality_probs` 和 = 1。

**用例**：① `restriction_count` 超过 `required_realm` 允许上限时给出明确拒绝；② 品质概率与表一致（同上蒙特卡洛）。

## 11. 任务引擎（quest）

**流程**：事件驱动推进（击杀/采集/交付/境界变化/打坐时长都发事件）→ DAG 前进 → 交付幂等。

**权威点**：前置、条件真实满足、幂等键 `uuid + questId + progressHash`（03 §4 `[锚]`）；进度入档、断线不丢（03 §8 `[锚]`）；支持末影箱内交付。

**表依赖**：`strife_quests`（JSON_SCHEMA §4.6）；交付文本走 `dialog_trees`。

**预算**：单玩家事件处理不得每 tick 遍历全部任务；按 flag/目标反查索引（`V-DAG` 生成期建索引）。

**用例**：① 手工矩阵覆盖每条序章节点（M3 准出）；② 双人同时交付不双发；③ 删表内一个引用 → 构建必须红（W4 演练，04 §6）。

## 12. 对话树（quest 内的 DSL）

**流程**：交互 NPC → 按 `conditions` 选分支 → 选项效果（flag / 声望 / 交付 / 开任务）。

**权威点**：条件求值在服务端（客户端只显示可达分支）；求值步数上限 1000、`max_depth` 16（JSON_SCHEMA §4.7），超限按 false 并记日志——防表写错死循环（03 §8 `[锚]`）。

**用例**：① 未知 flag/ID 的表构建失败（`V-DSL`）；② 环检测（A→B→A）加载期报错并给出指针；③ 序章 #10 两条择路文本都可达且互斥。

## 13. 灵气场与矿石（world）

**流程**：区块生成时算区域灵气（16×16 区块一值 + 细化层，03 §6 `[锚]`）→ 影响打坐速率 → 矿脉分布与再生（再生周期 H5，本期恒 null）。

**权威点**：世界级 saved data 存区域缓存；客户端只拿自己所在区域的值。

**用例**：① 新区块生成 ≤2ms/chunk（命中缓存 ≈0，03 §6 `[锚]`，进 CI 性能基准）；② 跨界移动速率即时切换且无 0 值；③ 同一种子两次生成世界灵气一致。

## 14. 兜底命令与审计（core）

命令树（03 §9 `[锚]`）：`/strife info`（**已实现**）、`quest reset <id>`（M3）、`realm set <realm> <sub>`（M1）、`lifespan set <n>`（M1）、`balance reload`（M2，仅开发环境）。

规则：全部 OP-only，全部写审计日志（log 文件即可，不建数据库，03 §4 `[锚]`）；日志命名空间 `strife/core`（02 §5）。**不实现不等于不报错**：未落地的子命令必须不存在（当前状态即如此），不能挂一个假装成功的空壳。

## 15. 客户端表现（client_fx）

- 只允许客户端入口注册，不得被逻辑包直接引用（03 §7 `[锚]`，依赖断言覆盖）。
- 面板/轮盘：原版 GUI + 粒子；无 shader（01 §5）。
- 音效：AI 生成短音效，台账记 `CREDITS.md`（04 §7）。
- 缺贴图回退占位纹理而非崩溃（04 §7 `[锚]`）；占位命名 `placeholder_<id>.png`，发版前清点挂 issue。
