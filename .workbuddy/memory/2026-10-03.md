## 核心结论：ID 不能用中文（物理约束，非风格偏好）
用户要求"模组内所有故事/物品命名都用中文"，但准确落点是 **ID 用 ASCII 拼音、玩家可见文本用中文**，理由三条：
1. 原版 `ResourceLocation` 只允许 `[a-z0-9_.]` → **中文 ID 加载期直接崩**（不是警告，是崩）
2. 1.21.1 掉落表路径由注册名唯一推导（`BlockBehaviour` 用 `withPrefix("blocks/")`）→ ID 与掉落表路径是**同一条约束**
3. Java 标识符可含 Unicode 但不可含 `-`；CSV 表头是列契约（改列名=破档）

**中文化审计结果（已达成，无需再动）**：lang 109 条全部含汉字、零空串、zh_cn/en_us key 双向完全对齐；对话正文 41 条全中文；代码内玩家可见文案 20 处全中文。

### 自己踩了两次的坑（都是"测试算错"不是"实现错"）
区域是 `floorDiv(chunk, 16)`：
1. 用"对角线遍历"想一次造冷与热 → `chunk=i*16` 落在第 i 个区域，256 块 = 256 个不同区域，区域内命中那条**根本没走到**
2. 改用 `i/16` 铺开 → 算出 16 次采样实际只有 1 次（`i<256` 时 `i/16` 只有 0..15，`baseX` 固定 → 仍在同一区域）

**结论：区域粒度是 16 时，"同一区域"只能靠 `% 16` 制造，靠 `/ 16` 只会换区域。**

# 2026-10-03 深夜②：真机第二连崩——OreTables.listResources 误传 `strife:strife_ores`

注册表修复后真机能进世界、任务/灵根/境界全正常，但 `/strife world ore status` 报**矿石表加载失败**。
`latest.log`：5 条 `Invalid path strife:strife_ores` + `no ore products under data/strife/strife_ores`。

**根因**：1.21.1 `ResourceManager.listResources(String, Predicate)` 收的是 `data/<命名空间>/` 之下的
**相对路径**（纯 `"strife_ores"`），**不是** `"命名空间:路径"`——带冒号被每个资源包判 Invalid path，
列出为空。`OreTables.listProductFiles` 传了 `"strife:" + PRODUCT_DIR`，**全仓 7 处 listResources 唯一写错**
（strife_pills/strife_realms/strife_core/strife_techniques/dialog_trees/StrifeOrdinalIndex 都对）。

**为什么通道 A/B 照不出**：单测直接把产物 JSON 喂给 `parseSpec(JsonObject, String)`，
不走 ResourceManager listing；`listProductFiles` 只有真机/真服才执行。又一次"运行时 listing 零覆盖"。

**修复**：`6cc06f3`（已挂 `fix/ore-datagen-format` 分支，前置 `8c1d87a`）。jar 重建（396258B）已装实例。

**教训**：`listResources` 的首参语义 = 目录相对路径；命名空间限定只能靠过滤器（`location.getNamespace()`）。
凡新写 listing 一律对照 `ProductionTables.listResources("strife_pills", ...)` 的写法。
