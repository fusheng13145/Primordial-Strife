## 1. 一条不可让步的红线

> **机器标识符用 ASCII 拼音，人类可读文本用中文。两者一一对应，映射只允许出现在 lang 文件与 CSV 的显示列里。**

这是**物理约束**，不是偏好：

| 约束 | 事实 | 后果 |
|---|---|---|
| Minecraft 资源 ID 只允许 `[a-z0-9_.]` | `ResourceLocation` 字符白名单由原版硬校验 | ID 写成 `灵玉矿` 会**加载期直接崩** |
| 1.21.1 掉落表路径由注册名推导 | `BlockBehaviour` 用 `withPrefix("blocks/")` 从 `ResourceLocation` 推出 | ID 与掉落表路径是同一条约束，改 ID 必须同步改表 |
| Java 标识符可含 Unicode 但不可含 `-` | `package com.strife.战斗` 合法但不可用 | `client-fx` 这类带连字符的目录名在 Java 里非法 |
| CSV 表头是列契约 | `JSON_SCHEMA.md` 锁死列名 | 改列名 = 破档（04 §5） |

"全部中文"在本项目的准确含义：玩家看到的每一个字都是中文（境界名、物品名、法术名、NPC 对白、GUI 文案、提示消息），承载它们的 ID 保持拼音。要求 ID 也用中文，等于推翻原版白名单——属改游戏本体，不在可动范围。

## 2. 五类命名的分区规则

| 类别 | 规则 | 语言 | 例 |
|---|---|---|---|
| **资源 ID**（注册名、lang key、产物文件名、CSV `id` 列） | `[a-z][a-z0-9_]*`，全小写，下划线分词，**不得含连字符与驼峰** | 拼音 | `block_ore_lingyu`、`pill_juqi` |
| **类名 / 包名** | `UpperCamelCase` / 包全小写无下划线，根包 `com.strife`（ADR-017） | 英文 | `OreTables`、`com.strife.world` |
| **玩家可见文本** | 简体中文；专有名词取 `content/LORE.md` 定名 | **中文** | 「灵玉矿」「火弹术」「凡人」 |
| **文档文件** | `NN-中文标题.md`，两位数字前缀维持排序 | **中文** | `10-当前进展与交接.md` |
| **配置 / 脚本** | 与被约束对象同名；Gradle 模块名全小写 | 英文 | `include 'content-base'` |

### 2.1 lang key 的构造

格式固定 `<类别>.<命名空间>.<id>`，与原版一致：

```
realm.strife.qili                    → "练气"
item.strife.pill_juqi                → "聚气丹"
block.strife.block_ore_lingyu        → "灵玉矿"
msg.strife.sit.start                 → "入定——气机流转。"
gui.strife.panel.title               → "修仙面板"
gui.strife.hud.realm                 → "境界 %s"      ← id 段可再点分
gui.strife.panel.affiliation.none    → "散修"          ← 分组.分组.叶子
```

- 类别前缀现役 12 个：`realm` `faction` `technique` `spell` `item` `block` `entity` `effect` `element` `gui` `msg` `key`；一律**单数名词**。
- **只有 lang key 的 id 段允许点分**（`gui`/`msg` 天然带二级分组），每段仍须 `[a-z][a-z0-9_]*`。
- **产物 `id` 字段与 CSV `id` 列是内容 ID，不点分**——等于 lang key 去掉 `<类别>.strife.` 后的那一段；用 `dialog.strife.nd_xxx` 当内容 ID 会被 V-NAME 拦下。
- 例外：`key.categories.strife` 是原版强制的键位分类 key，形态由 Minecraft 按命名空间决定，V-NAME 放行。
- **新增类别**先在 `JSON_SCHEMA.md` 登记再进 lang；`V-TEXT` 守 zh_cn/en_us key 双向对齐。

### 2.2 显示名（中文）的三个合法出处

中文名**只允许**出现在：① `assets/strife/lang/zh_cn.json` 的**值**（游戏内显示唯一来源）；② `tables/*.csv` 的**显示列**与 `_note` 注释列（给内容作者看，不进产物）；③ `content/` 四份真相源（设定定名来源）。别处出现即漂移源。

**禁止**在 Java 里硬编码中文界面文案当"临时方案"。面向玩家的字符串必须走 `Component.translatable("...strife.xxx")`，由 V-TEXT 守覆盖率。当前 `OreCommand` 的 `[OK]`/`[缺]` 属调试输出（运维判据，非玩家 UI），豁免且已记入 `docs/10`。

### 2.3 拼音取名

按**读音**取，不按字面：

| 中文 | 拼音 ID | 说明 |
|---|---|---|
| 灵玉矿 | `lingyu` | 正读 |
| 赤炎矿 | `chiyan` | 正读，不写 `chi_yan` |
| 寒玉矿 | `hanyu` | 正读 |
| 聚气丹 | `juqi` | 正读 |
| 青石观 | `qingshi` | 正读 |
| 筑基层 | `zhuji` | 正读（靠 `realm.` 类别区分同名不同字） |

规则：单字/双字词不拆，双字连写（`juqi` 不是 `ju_qi`）；多语义用下划线分隔（`ore_lingyu` 是"矿石·灵玉"）；多音字歧义在 `content/LORE.md` 术语表登记读音。

## 3. 目录结构约定

```
Primordial Strife/                    ← 仓库根 = 文档 + 真相源 + 工程
├── docs/                             手册（唯一参照）
│   ├── NN-中文标题.md                 分册，数字前缀排序
│   └── appendix/                      草案与调研（非规范）
├── content/                          真相源（NUMBERS/STORY/LORE/JSON_SCHEMA）
├── tables/                           策划填表区（CSV 唯一入口）
├── mod/                              ← Gradle 根（不是仓库根！）
│   ├── platform/                     主模块：core/realm/combat/production/quest/world/clientfx
│   ├── content-base/                 资源与 DataGen 产物
│   ├── tools/datagen/                产物生成器
│   ├── tools/validator/              门禁项
│   └── buildSrc/                     构建逻辑
└── .github/                          CI 与脚本
```

- **Gradle 根在 `mod/`**：在仓库根跑 `./gradlew` 会报 "does not contain a Gradle build"。
- 模块名全小写，多词用连字符（`content-base`）——Gradle 模块名不是 Java 包，允许连字符。
- **Java 包名一律不用下划线**（ADR-017）。
- 产物目录用 `snake_case`，必须由 DataGen 生成并与源表同提交（V-FRESH 守漂移）。

### 3.1 生成物与缓存不进版本库

```
/mod/build/    /mod/*/build/    /mod/*/run/    .gradle/
```

`mod/platform/run/` 是 `runClient`/`runServer` 工作目录（含 `config/`、`server.properties`、日志）。主工作树保留它是有意的（复用通道 1 现场），但它不是交付物——交付只认 `mod/platform/build/libs/*.jar`。

## 5. 新增内容的命名与用词自检清单

提交前逐条过：

- [ ] 资源 ID 全小写、下划线分词、无连字符、无驼峰
- [ ] lang key 类别前缀已在 `JSON_SCHEMA.md` 登记
- [ ] zh_cn 与 en_us **都**加了 key，zh_cn 值是中文，en_us 值非空串
- [ ] 中文显示名只在 lang / CSV 显示列 / `content/` 三处出现
- [ ] 面向玩家的文案走 `Component.translatable`，无硬编码中文
- [ ] **用词过 README 契约表**：无"法力/`mana`"、无裸用"灵气"指 `qi`、无"灵气值""跌境"当既成口径
- [ ] **引用的锚点存在且指向现行节号**（`05 §7` 这类错位不再新增）
- [ ] DataGen 产物与源表**同一个提交**
- [ ] 新建目录有归属说明，不落在 `mod/build/` 等生成物区
- [ ] `gradle :tools:validator:run` → `problems=0`
- [ ] `gradle spotlessCheck` → 绿
