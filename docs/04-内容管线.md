# 04 内容管线（content-base）

> 本章是项目核心竞争力所在："新增一章只填表 + 写文本"必须是可验证的事实，不是口号。

## 1. 数据流总览

```
tables/*.csv + content/NUMBERS.md + content/STORY.md     ← 人（或 Agent 起草、人审定）编辑的唯一入口
        │  DataGen（:tools:datagen）
        ▼
content-base/src/main/resources/data|assets/strife/...   ← 生成产物，带 @generated 头，禁止手改
        │  Validator（:tools:validator，PR 门禁 + 每晚全量）
        ▼
构建进 jar / 导出 content-base-X.Y.Z.zip（可独立替换）
```

规则只有一条：**生成产物永远不被手工编辑**。发现产物与源表不一致，以重新生成为准并回溯原因。

## 2. 内容目录与关键字段

| 目录（data/strife/ 下） | 内容 | 关键字段 | 生成器状态（2026-10-02） |
|---|---|---|---|
| strife_realms | 境界定义 | qi_max / lifespan / unlocks / breakthrough_success_key | ✅ NUMBERS `@@realms` 直出 + `rules.json` 运行时表 |

| strife_artifacts | 器图（炼器） | blank / restriction_count（禁制数） / core_slot / outputs（含品质概率） | ⚠️ 生成器在库，**表为空**（炼器玩法未做，G-3） |
| strife_quests | 任务 DAG（一章一文件） | prerequisites / objectives / rewards / timer / fail_goto | ✅ `quests_<章>.csv` |

| lang | zh_cn / en_us | key 与内容 ID 同源 | ✅ 手写种子 + DataGen 键对齐校验 |

MVP 只填 realms/techniques/spells/pills/artifacts/quests/dialog_trees 与序章 lang；符箓/阵法/灵植表目录在 EP0 仅占位不填（09 分册 F，玩法归 EP1）。

> **填表即反馈**：`tables/` 下任何 CSV 只要填了行却没有注册生成器，`DataGenMain` 会**直接报错并指名这张表**，不会静默丢弃（已实测）。反之填了行且有生成器，产物缺失会被 V-FRESH 拦下。

字段级契约以 `content/JSON_SCHEMA.md` 为准；表结构变更 = 改 SCHEMA + DataGen + Validator 三处同一 PR。

## 3. 章节交付单元

每章交付 = **任务 DAG + 对话树 + 奖励/掉落表 + 新增内容资产 + zh_cn 文本（en_us 占位）**，五件套缺一即章未完成。序章目标 45 分钟通关，M3 交付全部序章节点；第一章主题待 STORY.md 定稿（已知第二章主题"五行灵珠"）。

## 4. ID 与命名规范

- 格式：`<域>_<章>_<语义>`，全小写下划线。示例：`ch2_pearl_water`、`tech_qingxin_jue`、`quest_prologue_meditation_01`。
- 域前缀固定枚举：`tech_ / spell_ / pill_ / qi_ / quest_ / dlg_ / npc_ / block_ / item_ / ch<N>_`。
- **lang key 与内容 ID 一一映射**：每个内容 ID 必须有 `item.strife.<id>` 等对应 key，zh_cn 缺失即构建失败（D4：en_us 先以占位串过 CI）。
- 重命名 ID 视同破档：须 ADR，且保留旧 ID 迁移映射一个主版本。

## 5. DataGen 规范

- 输入：CSV 表（UTF-8，首行表头，注释列以 `_` 开头）、NUMBERS.md 数值块（解析约定见 05 分册）、STORY.md 大纲（仅任务骨架生成用）。
- 输出：确定性排序（同输入必同产物，diff 可读）；文件头注入 `@generated from tables/xxx.csv` + 源表哈希。
- 运行：`./gradlew :tools:datagen:run`，本地与 CI 均跑；产物 diff 未提交视为 CI 失败（"生成器漂移"检查）。
- DataGen 代码属开区，Agent 可直接维护。

## 6. Validator 校验项（全部构建期，PR 必过）

> 括号内为 2026-10-03 实测的 `checks` 计数口径：当前 **12 项**，由 `./gradlew :tools:validator:run` 输出 `checks=12 problems=0` 验证。

| 检查 | 内容 | 状态 |
|---|---|---|
| V-DUP 重复 ID | 全域唯一；台账表（首列非内容 ID）与对话文本配对表显式豁免 | ✅ |
| V-FRESH 产物新鲜 | `@generated` 头哈希与当前源表一致（含 `content/` 真相源派生域） | ✅ |
| V-DAG 连通 | 任务图无环、从章节入口可达全部必做节点、奖励闭环 | ✅ |
| V-REF 一期 | 跨表引用不得悬空（材料/产出/法术/前置任务/lang key） | ✅ |
| V-REF 二期 | 源表主键 / lang item 键 / LORE NPC 卡存在性（占位符走白名单） | ✅ |
| V-GROWTH 成长比 | 查 NUMBERS 区间表：成长比 1.8–2.5、成功率 0–1、寿元单调递增 | ✅ |
| V-RANGE 数值域 | 真相源数值区间越界检查 | ✅ |
| V-PROB 概率归一 | 丹方/掉落 outputs 概率和 = 1（容差 1e-6） | ✅ |
| V-TEXT 文本缺项 | zh_cn 全覆盖；en_us 允许占位但不得为空串（对话域显式豁免） | ✅ |
| V-DSL 合法 | 对话条件表达式词法/括号/谓词白名单/effects args 正则；独立词法校验器 `DslSyntax` | ✅ |
| **V-NAME 命名规范** | **ID 用拼音、文本用中文**（[11 分册](11-命名与目录规范.md)）：ID 形状 `[a-z][a-z0-9]*(_[a-z0-9]+)*`、禁中文 ID（会崩）、lang key 三段式、zh_cn 值必含汉字；源表与产物两侧同查，台账表只查非 ASCII 字母 | ✅ |
| price 非负 | H1 价格字段非负 | ✅ |

`content/NUMBERS.md` 缺席时，V-GROWTH / V-RANGE 侧自动跳过并在输出中声明（不静默通过）。

Validator 报错必须给出**文件路径 + JSON pointer + 人话说明**（这是 Agent 能否自助修复的关键，见 06 分册）。W4 演练（固定动作代号，时点与两阶段拆分见 07 §6）：故意在表中留一个悬空引用 → 构建必须失败。演练实测记录见 [`appendix/W4-演练记录.md`](appendix/W4-演练记录.md)。

## 8. CI 门禁清单（PR 必过）

```
spotlessCheck → build → unitTest（realm/quest 单测 100% DAG 用例）
→ datagen 新鲜度 → validator 全项 → 模块依赖断言 → server jar headless 冒烟 → 附件内存快照测试
```

每晚任务追加：性能基准（tick 采样、灵气场 chunk 生成耗时）、蒙特卡洛 10 万次丹方期望抽样、纯净 jar 2 小时长跑冒烟（M5 起）。

两条容易踩空的地方（均为"看起来绿其实没跑"的形态，CI 必须显式防住）：

- **buildSrc 的测试不会被主构建执行**：主构建只编译 buildSrc，不跑它的 `test` 任务。模块依赖断言的用例（`ModuleDependencyRulesTest`）必须靠 `./gradlew -p buildSrc test` 显式触发。
- **单测执行要有计数断言**：`build` 绿与"某模块测试被静默跳过（NO-SOURCE / 缺 junit engine）"并不矛盾。CI 末尾对 buildSrc / platform / tools:validator / tools:datagen 各自断言 ≥1 用例，并把逐模块计数写进 step summary。

## 9. 内容热更新

- `content-base-X.Y.Z.zip` 作为独立资源包可被整合包作者替换；加载顺序：内置内容 → 外部资源包覆盖（同 ID 覆盖须在 Validator 白名单内，防误伤）。
- 平台层与内容层版本契约：平台 jar 声明 `contentFormatVersion`，内容包标注自身版本，不匹配只警告不崩溃（兼容一个区间）。
