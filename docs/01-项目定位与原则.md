# 01 项目定位与原则

## 1. 一句话定位

面向 Minecraft 1.21.1 NeoForge 的**大型修仙模组**：以章节化剧情驱动修仙成长（灵根→修炼→突破→渡劫→飞升），并把「内容产能」做成工程能力——数据驱动、构建期校验、新增一章只填表写文本、不改逻辑代码。

**长期愿景（D9）**：终局形态是**高自由度修仙大世界**——可入宗门可行散修；世界有主线级事变（人妖大战、外敌入侵）与宗门间对立合纵，玩家在事变中择路而非旁观；前期交付的只是地基与第一批原语。由此得出工程第一原则：**可扩展性优先、耦合必须低**。早期功能允许变形（主线可周期化、单宗门可多阵营化），凡"变形需要改代码"的设计在评审层驳回（03 §2.1）。远期内容域全部登记在 09 图谱，扩展走钩子（03 §10 H1–H7）+ ADR，不做临时发明。

## 2. 差异化主张

1.21.1 修仙模组生态里玩法堆料者众，普遍缺三样：**章节化叙事、可校验的任务链、内容独立更新能力**。本项目的产品本质是"修仙内容平台 + 生产线"，模组只是它的第一个交付。这三样既是对外竞争力，也是对内取舍的裁判——凡不服务于这三样的需求，默认拒绝。

玩法层的辨识度由**境界为骨、御兽为肉**（D11）提供：境界轴保证长线目标与叙事重量，御兽轴保证每个玩家的 build 与游玩路径不同。

## 3. 三层交付物

| 层 | 内容 | 变更节奏 | 所有权 |
|---|---|---|---|
| 平台层 | core / realm / combat / production / quest / world / clientfx 逻辑代码 | 稳定、少变 | 本人（core、realm 唯一写权；灰区可交 Agent，受 06 分区约束） |
| 内容层 | content-base：境界/功法/法术/丹方/任务/对话/文本/贴图 | 持续增量、可独立更新 | 本人 + Agent（开区） |
| 工具层 | DataGen / Validator / 表格模板 / CI | 跟随内容管线演进 | 本人 + Agent（开区） |

## 4. 目标用户

- **修仙题材玩家**（全年龄段，不要求读过修真小说）：追求境界成长、剧情代入与长期目标（寿元压力、成长曲线）。中核定位：需要规划与查阅，但不以读外部 Wiki 为游玩前提（引导口径见 07 §4.2、D12）。
- **和朋友一起游玩的人**：单人与多人同一套架构（D3），多人是"熟人共修"而非竞技（对战边界见 D13）。
- **整合包作者**：需要内容可独立替换、接口稳定、纯净 jar 可单独部署。
- **单人长期游玩者**：相邻境界成长比 1.8–2.5 的曲线支撑可持续目标（05 §2）。

## 5. 明确不做（硬边界）

"顺便做一下"先回到这张表。新系统立项必须写 ADR 并经本人批准。

| 不做项 | 说明 |
|---|---|
| MMO 化 | 无交易行、无跨服、无实时经济系统 |
| 反作弊军备竞赛 | 不做客户端完整性对抗、不做封禁与举报体系；服务端只做**自身数值权威校验**（03 §4） |
| 竞技级平衡 | 不做天梯、赛季、meta 平衡体系（玩家对战边界见 D13） |
| 自定义渲染管线 | 不写 shader，不与钠/Iris 抢渲染权 |
| 追新版本 | 锁定 1.21.1 直至主线完结；多版本并行明确放弃 |
| 通用脚本引擎 | 对话条件仅用内置 DSL，不引入 Nashorn/GraalJS |
| 玩家自建内容工作台 | 面向整合包作者的是"填表 + 资源包替换"，不做起装器/编辑器 GUI |
| 双修与炉鼎题材 | 列入不做清单（ADR-013） |

## 6. 成功标准（全部进 CI 或手工用例矩阵）

| 指标 | 目标值 | 验收方式 |
|---|---|---|
| 新手引导 | 进服到序章完成 ≤45 分钟，不因机制不明卡死 | 手工用例矩阵（每里程碑） |
| 稳定性 | 单人连续 2 小时无崩溃、内存增长 <200MB、tick 耗时符合预算 | 性能基准（CI 每晚 + 发版前） |
| 内容产能 | 新增一章只需填表 + 写文本，零逻辑改动 | W4 演练两阶段（07 §6）：断链→构建失败；3 天产出一章 playable |
| 内容正确性 | 任意任务断链、悬空引用在构建期被发现 | Validator（PR 必过门禁） |
| 验收不堆积 | **未实机验证项累计 >20 条即停止开新功能**（D14） | `deliverables/待验证台账.md` 计数 |

## 7. 核心玩法循环

灵根决定天赋 → 打坐积累修为 → 突破解锁境界、寿元与机制位 → 任务驱动剧情 → 战斗与生产供给资源 → **收服与培养灵兽，改变战斗与生产的实现方式** → 世界环境（灵气浓度/宗门/上界）调节效率 → 变强后解锁更多内容。

闭环每一步都必须能回到 NUMBERS.md 查表，**不允许存在代码里写死的成长数值**。玩家间对战与宗门关系不改变这条主轴，只是同一批原语的另一组剧本（03 §2.1）。

## 8. 玩家类型与模块映射

| 玩家类型 | 核心内容 | 对应模块 |
|---|---|---|
| 修仙成长型 | 境界、灵根、寿元、渡劫 | realm |
| 战斗型 | 功法、法术、法宝、妖兽、御兽 | combat |
| 生产型 | 炼丹、炼器、灵植 | production |
| 剧情型 | 任务 DAG、对话树、章节叙事 | quest |
| 探索型 | 灵气浓度地理、矿脉寻访、秘境、宗门/上界踏勘 | world |
| 对抗型 | 玩家对战、势力归属、宗门对立 | realm + combat + world（D13） |
