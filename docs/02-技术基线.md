## 2. 第三方依赖矩阵

| 依赖 | 用途 | 侧 | 策略 |
|---|---|---|---|
| Patchouli | 游戏内手册 | client | 21.1 版已核实存活；仅软依赖（`modRuntimeOnly` + optional），无 Patchouli 时面板降级 |
| Accessories（取代 Curios） | 法宝饰品槽 | both | 已核实 21.1 版；备用：自研极简饰品槽（1 个 attribute + 1 个 GUI 槽） |
| JEI | 配方查看 | client | 软依赖；配方接口自实现 `RecipeInput` 标准协议 |
| GeckoLib | 实体动画 | client | **M2 不引入**（D5）。预留 `AnimationProvider` 接口，M5 后可选接入 |

规则：
- 新增任何依赖 = ADR + 版本写入 `gradle.properties` 顶部集中管理，禁止散写。
- 所有第三方库通过 `jar-jar` 嵌入或声明为 required 依赖二选一，禁止"恰好能跑"的 classpath 巧合。
- 软依赖一律用 `ModList.get().isLoaded()` 隔离，禁止在非安全路径直接引用软依赖类（防无该库时崩溃）。

## 3. 仓库与模块布局

单仓库（monorepo），Gradle 多模块：

```
<repo>/                        # 根目录 = 本机 clone 目标名，不承载任何 ID 语义（见下"路径说明"）
├── docs/                        # 本手册（唯一参照）
├── content/                     # 真相源：NUMBERS.md / STORY.md / JSON_SCHEMA.md / LORE.md
├── mod/                         # Gradle 根工程
│   ├── platform/                # 平台层：一个 MOD 制品，按包划分模块
│   │   └── src/main/java/com/strife/
│   │       ├── core/            # 注册、事件总线、附件、网络框架、命令框架
│   │       ├── realm/           # 境界/灵根/修为/打坐/突破/寿元
│   │       ├── combat/          # 功法/法术/法宝/妖兽 AI
│   │       ├── production/      # 统一配方机（丹/器/符/阵/种）
│   │       ├── quest/           # QuestEngine/对话树 DSL
│   │       ├── world/           # 灵气场/矿石/宗门结构/上界维度
│   │       └── client_fx/       # 面板/轮盘/粒子/Patchouli（仅客户端加载）
│   ├── content-base/            # 内容层：纯 resources，无代码
│   │   └── src/main/resources/
│   │       ├── data/strife/    # strife_realms/ strife_techniques/ strife_spells/
│   │       │                    # strife_pills/ strife_artifacts/ strife_quests/
│   │       │                    # dialog_trees/ worldgen/ loot_table/ recipe/ advancement/
│   │       └── assets/strife/  # 贴图/模型/音效/lang(由生成器产出)
│   ├── tools/
│   │   ├── datagen/             # DataGen：NUMBERS.md/表格 → 游戏 JSON
│   │   └── validator/           # 构建期内容校验器（纯 JVM，不启动 MC）
│   └── buildSrc/                # 模块依赖图断言、发布任务
├── tables/                      # 策划表格（csv，DataGen 输入）
└── .github/workflows/           # CI（见 04 分册 §8）
```

要点：
- **平台层是一个 MOD 制品、包级模块化**。不做微服务式多 MOD 拆分——3–4 人团队养不起跨制品版本矩阵，包边界靠 CI 依赖断言强制（03 分册 §2）。
- **Java 包根统一 `com.strife.`（ADR-017），工具与构建代码不例外**：platform 用 `com.strife.<模块>`，tools 用 `com.strife.tools.<工具>`，buildSrc 用 `com.strife.conventions`（Gradle 插件 ID 仍为 `strife.conventions`，插件 ID 不是包名）。
- `content-base` 是纯资源模块，禁止出现 `src/main/java`（CI 检查由 `:content-base:checkImports` 执行；该检查在 `src/main/java` 不存在时也必须正常通过，缺目录 ≠ 违规）。
- client-fx 包只允许 `@OnlyIn` 语义下的客户端入口注册（用 NeoForge 分侧 ModEntrypoint），保证纯净 jar 可裁剪（03 分册 §7）。

## 4. 环境搭建（新成员 30 分钟目标）

```bash
# 前置：JDK 21（temurin）、Git、IntelliJ IDEA Community（推荐）或 VSCode
git clone git@github.com:fusheng13145/Primordial-Strife.git "<repo>" && cd "<repo>/mod"
./gradlew --build-cache genSources     # 首次约 5–10 分钟
./gradlew :platform:runData            # 跑通 DataGen（M0 后）
./gradlew :platform:runClient          # 进游戏，聊天栏出现 strife 命令即成功
./gradlew :platform:runServer          # 纯净服务端验证（M0 准出项）
```

- **路径说明**：仓库根目录名 = 本机 clone 目标（当前为 `Primordial Strife`，含空格），它不是技术 ID——一切 ID/命名空间/产物名以 ADR-017 的 `strife` 为准。**含空格路径对 Gradle 一般安全，但个别脚本/工具会踩坑：新成员首选 clone 到无空格路径（如 `D:\work\strife`）**；仓库内脚本引用根目录一律用 `"<repo>"` 带引号写法，禁止硬编码绝对路径。
- **Windows 硬约束：clone 路径必须纯 ASCII（不得含中文等非 ASCII 目录名）**。非 ASCII 路径 + 系统 ANSI 代码页（简体中文 Windows 默认 GBK/936）下，Gradle 以 UTF-8 写出 worker 的 classpath `@argfile`，而 JVM 启动器按平台 ANSI 编码读取该文件 → 测试 worker 启动即 `ClassNotFoundException`，`./gradlew test` 全量失败（编译与 `java -cp` 直跑同一路径均正常，可据此判定）。上游缺陷：gradle/gradle #30304（修复进 9.7.0）、#30391（未修复）。此时**不得**通过改 `systemProperty`/`jvmArgs` 或跳过测试来掩盖；结论是换路径，不是换代码。

- Gradle daemon + build cache 常开；CI 与本地共用同一份 `gradle.properties` 内存参数，避免"本地能跑 CI 红"。
- Windows 成员统一用 Git Bash 执行脚本，仓库内脚本禁止 PowerShell 专有语法。
- **`runServer` 前需自备 `mod/platform/run/server/eula.txt`（内容 `eula=true`）**：该目录不入库，首次运行不会自动同意，否则服务端启动即退出。同意 Mojang EULA 属个人操作，各成员自行确认。
- **`runClient` 首屏日志可能出现 `authlib ... Read timed out`（session/realms 域名网络受限）**：这是账号会话检查，不影响 MOD 载入与主菜单进入。判定"载入成功"以这三行为准——mod 列表出现 `Primordial Strife x.y.z (strife)`、`strife platform entry constructed`、`ResourceManager: ... mod/strife ...`。

## 5. 代码规范（对人和 Agent 同等生效）

| 项 | 规范 |
|---|---|
| 语言级别 | Java 21；鼓励 record / sealed / pattern matching |
| 风格 | Google Java Style 变体：4 空格缩进、120 列；Spotless 格式化，`./gradlew spotlessCheck` 进 CI |
| 静态检查 | Error Prone（或 Checkstyle 简化集）；新代码不得新增抑制注释，存量抑制须挂 issue 号 |
| 命名 | 类/方法英文；内容 ID 全小写下划线（04 分册 §4）；禁止拼音缩写混入代码命名 |
| 魔法数字 | 禁止。数值一律查表或从 DataGen 产物读取，违规由 Review 拦截 |
| 注释 | 默认不写；只写"为什么"，引用 ADR/issue 编号 |
| 异常 | 服务端逻辑禁止吞异常；内容加载失败必须 fail-fast 并报出具体 JSON 路径 |
| 日志 | 统一 `Logger`（命名空间前缀 `strife/<module>`）；tick 热路径禁止 info 级以上日志 |
| 提交 |  Conventional Commits（`feat(realm): ...`）；一个小提交一件事，禁止"AI 大改动"式万行提交 |
| 分支 | `main`（受保护）← PR；`beta/X.Y`（M6 起）；Agent 一律在 `agent/<任务号>-<slug>` 分支工作 |

## 6. 存档兼容基线

- 玩家数据全部走 NeoForge **Attachments**（`AttachmentType` 注册于 core），世界级数据走 saved data / 区块 NBT。
- 新增字段必须带默认值；删除字段保留 reader 兼容一个主版本；**破坏性变更 = 数据大版本号 +1，且必须 ADR**。
- 每次改数据结构的 PR 必须附带"重载存档三次一致"的手工用例结论（07 分册准出条件）。
