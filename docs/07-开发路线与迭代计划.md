# 07 开发路线与迭代计划

> 本册定义**单人独立开发**的工作模式、阶段划分与后续全量路线。历史里程碑保留 M0–M4 编号（便于旧文档与提交记录对照），未来阶段统一用 P0–P6 编号。
>
> 路线是**计划不是承诺**：每阶段启动时按当时代码与证据重新估算，量级只用于排批次。准出条件才是合同（§2）。

## 1. 工作模式：单人 + AI Agent

| 角色 | 职责 | 边界 |
|---|---|---|
| **本人** | 唯一决策者、实现者、审核者、真相源确认人、发布负责人 | 核心逻辑（core/realm）由本人写；所有 ADR、破档、门禁变更由本人拍板 |
| **AI Agent** | 探索、起草、实现灰区/开区改动、写测试、填表、生成文本与占位资产、跑验证、整理文档 | 产出默认"未验收"；不得自批、不得改门禁让它变绿、不得代本人确认真相源 |

规则：

- 文档不再按人员角色分工组织。历史文档中的 A/B/C/D 是已废止的四人分工称谓（ADR-024），阅读时统一理解为"本人"。
- Agent 的产出必须经过 §8.3 的四道复核，才允许进入交付。
- 一个批次只推进 **1 条主线** + 至多 **1 条内容/文档线**；并发是返工的主要来源。
- 决策只认 ADR、手册与真相源；聊天记录、口头约定、Agent 的"我记得"都不算依据。

## 2. 推进原则

- **准出条件合同**：每阶段只锁准出条件，不锁功能清单细节。准出条件不因进度压力降级。
- **批次制**：1 批 ≈ 1 个有效工作日。每批必须有可复现的证据（命令输出、测试报告、截图/日志、提交哈希）。
- **WIP 上限**：同时进行的主线 ≤1，内容/文档线 ≤1；未合并实验分支 ≤1。
- **砍范围顺序**：世界系统 → 表现 → 支线内容；**主链、内容管线、realm 永不砍**。
- **新增系统必须 ADR**：09 图谱是地图不是待办；图谱外临时发明一律拒绝。
- **每批收尾**：更新 [`10-当前进展与交接.md`](10-当前进展与交接.md) 快照与 [`../deliverables/待验证台账.md`](../deliverables/待验证台账.md)；未验证项写"未验证"，不得写"已完成"。
- **证据口径**：结论必须挂可重生成的命令或可复核的记录；凭印象写数字视为缺陷（R9/R12）。

### 4.2 P1 发布候选（M5）

**目标**：序章 + 第一章完整可玩，达到可对外发布的候选质量；玩法、内容、表现、稳定性四条线同时收口。

**主要任务**

1. **第一章完整化**：把现有 6 个骨架节点扩成完整章节（任务 DAG、对话、奖励、地点/NPC、章节首领/告别节点）；至少 2 条可选支线；关键情感节点由本人重写。
2. **序章打磨**：按 P0 通关记录修卡点、补引导与提示；任务追踪条覆盖第一章；NPC 摆放与对话树一致性复核。
3. **战斗与生产**：法宝槽收口（属性/耐久/GUI）；法术/法宝命中反馈、粒子、音效；妖兽技能预警；配方查看（JEI 或命令增强）；丹药/炼器平衡。
4. **世界表现**：宗门厅堂形态（LORE 定稿）、上界至少 1 个可探索点、灵气场观感调优。
5. **手册**：Patchouli 或自研面板，覆盖境界/修炼/战斗/生产/任务五域；无手册时命令必须能完成所有操作。
6. **本地化**：en_us 全量占位过 CI，序章 + 第一章精修；zh_cn 全量终审。
7. **稳定性与发布**：2h 连续运行、内存增长 <200MB、tick 预算；占位资产清点清零或挂账；主 jar / 服务端 jar / content-base 包三制品；changelog 与安装说明。

**交付物**：RC 制品三件套；第一章 playable；手册；en_us；手工用例矩阵与性能报告；发布检查单。
**准出条件**：01 §6 成功标准全部有证据；第一章可完整通关；2h 稳定；占位清单闭环；全量门禁绿。

**依赖**：P0 准出；D-P0-1/D-P0-2 决策；第一章文本产能。
**不做**：EP1 经济系统、新维度体系、多人功能加固（只做服务端权威审计）。

### 4.8 阶段闸门、依赖与砍范围

- **进入下一阶段的条件**：上一阶段准出条件全绿 + 稳定窗口无 P0 缺陷 + 本阶段范围闸门（in/out 清单）已写。
- **依赖链**：P0 → P1 → P2 → P3 → P4 → P5 → P6；P3–P6 之间共享 H1–H7 与内容管线，不得跳阶段抢跑。
- **砍范围顺序**：世界系统 → 表现 → 支线内容；主链、内容管线、realm 永不砍。
- **范围闸门**：每阶段启动时在 10 册写"本阶段做/不做"两列；范围外需求一律进 09 图谱或拒绝，不临时发明。
- **稳定窗口**：每阶段末至少 1 个批次只修不加；修不完的问题进下阶段欠账台账。

## 8. 单人工作节奏与并发控制

### 8.1 日批次模板

1. **开工**：从 P 阶段工单池取 1 条主线；写清验收命令与证据路径。
2. **红先**：行为改动先写失败测试；没有红脸就不写实现。
3. **实现**：只动工单范围内文件；超范围的重构另开工单。
4. **门禁**：`spotlessCheck build test validator`；Windows 中文路径下测试走 ASCII worktree。
5. **收尾**：更新 10 册快照与待验证台账；记录未验证项；提交信息按 Conventional Commits。

### 8.2 WIP 与分支

- 同时只开 1 条代码主线 + 1 条内容/文档线；第三条一律排队。
- 分支：`leyon` 日常集成；`agent/<任务号>-<slug>` 只做未验证实验；实验失败就丢弃，不带入交付。
- 未合并实验分支 ≤1；超过说明在并行逃避收口。
- 大改动先写 ADR 草案，再动代码；破档改动必须单独批次。

### 8.3 独立复核四道防线（替代第二个人类）

单人开发没有第二双眼睛，用流程替代：

1. **红先测试**：每个行为改动先看失败，再写实现；测试失败原因必须是功能缺失，不是编译错误。
2. **全新上下文复核**：高风险改动（core/realm、公共契约、破档、门禁）派一个**没有实现上下文**的 Agent 只读复核 diff 与规格，专找"假绿、越界、未验证断言"。
3. **外部门禁**：CI + Validator + 模块依赖断言 + 纯净 jar 冒烟；门禁红就是红，不许改门禁。
4. **实机证据**：涉及游戏内行为的改动，必须有本人实机操作记录；Agent 不得自证。

> 复核结论写进 PR 描述或 10 册；"我看过了"不算证据。

### 8.4 决策与文档同步

- 任何系统级取舍先写 ADR（08 册），拍板后 24 小时内同步到对应分册正文。
- 真相源变更：先改 `content/`，再跑 DataGen + Validator，最后同步 10 册；不允许"根据代码反推真相源"。
- 文档引用使用章节锚点或提交哈希，不写易漂的行号；跨分册引用必须写清"分册号 + 小节标题"。
- 历史文档中的角色称谓不追溯改写；在文首标注"历史草案，A/B/C/D 已废止"即可。

### 8.5 停线规则

出现以下任一情况，停止当前批次并先修复：

- 门禁红且原因未定位；
- 真相源与产物冲突；
- 第三方 API 行为无出处（未验证）；
- Agent 产出出现假绿测试、越权重构或删除断言；
- 同一缺陷连续两次修复失败（转 systematic-debugging，不再猜）。

### 8.6 进度口径

- 进度只按**准出条件**和**证据**报，不按"感觉完成了百分之几"报。
- 每阶段结束给三行：已达成（证据）、未达成（原因）、下一阶段入口条件。
- 对外承诺只用 W4 演练实测出的"新增一章耗时"，不用规划批次换算。
