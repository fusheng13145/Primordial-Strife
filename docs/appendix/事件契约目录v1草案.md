## 1. 三条上位规则（03 §2 / §4，逐条可查）

1. 跨模块通信只有两种手段：**NeoForge 事件总线 + core 自定义事件**，或 core 的只读接口。出现"模块 B 直接读写模块 A 的 Attachment"即架构违规（风险 R5）。
2. **新增自定义事件 = 在 core 声明 + 附 Javadoc 载荷契约 + 单测**（03 §2 末条）。别的包一律不得定义被跨包订阅的事件类。
3. 事件只在**服务端**签发（03 §4 服务端权威）。任何事件的载荷都不得取自客户端上报值；客户端只通过 S2C 同步通道看到结果（§6）。

## 2. 总线、线程与优先级约定

| 项 | 口径 |
|---|---|
| 总线 | 全部 strife 自定义事件走**游戏总线** `NeoForge.EVENT_BUS`（`net.neoforged.neoforge.common.NeoForge`）。mod 总线只用于注册期，不承载玩法事件 |
| 线程 | 服务端主线程（tick 线程）。订阅者**禁止**做阻塞 I/O、禁止起线程、禁止持有跨 tick 引用（事件对象不得被存进集合复用） |
| 优先级 | 结算类订阅用 `EventPriority.NORMAL`；QuestEngine 进度推进用 `NORMAL`；审计日志/统计用 `LOWEST`。**禁止用最高/最低优先级去绕开他人的取消判定** |
| 重入 | 订阅者内禁止 `post` 同类事件。链式触发的深度上限 `[拟] 8`，超限记 `strife/core` WARN 并断链——防"表/脚本写错→栈溢出"（与对话 DSL 的求值步数上限同一思路） |
| 异常 | 单个订阅者抛异常不得吞掉后续订阅者；NeoForge 总线行为以官方实现为准，**落码前须实测确认**（会签要点 2） |
| 取消 | `ICancellableEvent`（`net.neoforged.bus.api.Event` 的兄弟接口，bus 8.0.5 提供）。**只有"结果尚未签发"的事件才可取消**；已结算的结果事件一律不可取消（否则客户端会与服务端不一致） |

## 3. 事件清单 v1

标注：**C** = 实现 `ICancellableEvent`；发起方 = 唯一允许 `post` 的包。载荷列里的 `StrifeData.*` 是 core 聚合附件的字段（03 §3），`域:键` 指向 NUMBERS.md 块。

| 事件 | 发起 | 预期订阅 | 载荷（契约字段） | 频率上限 | C | 取消后果 |
|---|---|---|---|---|---|---|
| `QiChangedEvent` | realm | quest、client_fx 同步层 | `player`、`oldQi`、`newQi`、`source` ∈ `sit/pill/quest/breakthrough/refund` | 打坐按时间片签发（`sit:tick_interval_ticks`），非每刻；单次任务奖励 = 1 次 | 否 | 结果已签发，不可否决 |
| `PlayerBreakthroughEvent` | realm | quest、combat（解锁法术）、client_fx | `player`、`fromRealm`、`toRealm`（ordinal，core 不认识枚举）、`success`、`attempts`、`tribulation`、`successRateUsed` | `bt:breakthrough_per_min` 限速由命令/意图层保证，事件本身不限 | 否 | 失败代价（`bt_cost:*`）已算完才发，供订阅方反应 |
| `DashengSettlementEvent`（大限） | realm | quest、client_fx | `player`、`realmBefore`、`realmAfter`、`lifespanResetTicks`、`debuffKey` | 每玩家每境界至多一次 | 否 | 非破坏性（D6）已结算，订阅方不得再"追加惩罚" |
| `SpiritrootRefinedEvent`（洗髓） | realm | combat、quest、client_fx | `player`、`qualityBefore/After`、`elementsBefore/After`（位掩码 bit0 金…bit4 土）、`disabledTechniques`（内容 ID 列表） | 道具驱动，无固定频率 | 否 | **必须带 `disabledTechniques`**：03 §8 禁止静默失效，面板致灰靠它 |
| `EntityKilledByPlayerEvent` | combat | quest（DAG 进度）、production（妖丹/掉落） | `attacker`、`victim`、`victimTypeId`、`damageSourceKey`、`lootRolledWithLuck`（H6 快照，默认 1.0） | 同屏 ≤64 法术实体红线内 | 否 | 掉落已由服务端抽完才发；**不要**在这里补发掉落 |
| `AmbientQiChangedEvent` | world | realm（速率缓存失效）、client_fx | `regionId`、`oldRatio`、`newRatio`、`causeKey`（H5 周期键，本期恒 `manual`） | 区域粗粒度（16×16 区块一值），整片变更合并为 1 次 | 否 | 环境系数变更是事实，不做否决 |
| `FlagChangedEvent` | core（由 quest 侧结算入口调用） | world、client_fx、后续 H3 通缉 | `player`、`flagKey`（`<域>:<章>:<语义>` 冒号分段，03 §10 末口径）、`oldValue`、`newValue` | bitset 写入即发，`flags` 是 `long`，故**至多 64 键**；超限走 ADR 扩存储 | **是** | 可否决"标记置位"（例如剧情保护期禁止置 `dead` 位）；否决后 bitset 保持旧值 |
| `ReputationChangedEvent` | core（H2 向量写入点） | quest、world、client_fx | `player`、`factionId`、`oldValue`、`newValue`（clamp 到 [-100,100]）、`reasonKey` | 一任务一faction一次；批量交付须合并 | **是** | 可否决某次涨跌（宗门叛逃免罚之类剧本钩子）；否决的是**本次增减**，不是历史 |

### 3.1 只声明、本期不 post 的钩子事件（03 §10 要求"结构从 M0 就在"）

| 事件 | 归属钩子 | 本期状态 |
|---|---|---|
| `PeriodOpenedEvent` / `PeriodClosedEvent` | H5 全局时钟 | core 里留类与载荷（`periodId`、`windowSec`、`conditionKey`），调度器 M4 接；**无人 post 不算违约** |
| `PlaneMigrationEvent` | H4 位面接口 | 留 `entity`、`fromDimension`、`toDimension`、`attachmentProjectionKey`；EP4 消费 |
| `WarPhaseChangedEvent` | H7 战争状态机 | 留 `warId`、`phaseIndex`、`belligerents`、`consequenceKeys`；剧本全部来自 `strife_wars` 表，代码不含战争判断 |

### 3.2 明确**不新建**事件的场景（避免与原版重复、避免热路径发事件）

| 场景 | 用什么 | 理由 |
|---|---|---|
| 玩家死亡/重生 | 原版 `PlayerEvent.Clone`（NeoForge 21.1 已靠它做 `copyOnDeath`） | 附件复制策略已在 `StrifeAttachmentTypes.PLAYER_DATA` 声明，再发一次事件会出现两份"谁保留什么"的口径 |
| 生物死亡本体 | 原版 `LivingDeathEvent`（`net.neoforged.neoforge.event.entity.living`） | 归属与掉落判定属 combat，`EntityKilledByPlayerEvent` 只在 combat 判定完成后发 |
| 区块加载/卸载 | 原版 `ChunkEvent.Load`（`event/level`） | 灵气场缓存属 world 内部，跨模块无人订阅 |
| 服务器生命周期 | 原版 `ServerStartedEvent` 等（`event/server`） | 状态复位（H5 时钟、区域缓存）在发起方本地做 |
| **寿元逐刻流逝、玩家位置变化、当前修炼速率** | **不发事件**，改为按需查表/查附件 | 03 §6 红线：单玩家附加逻辑 ≤0.05ms/tick。每刻一事件等于把 tick 变成广播风暴；只有**结算结果**（大限）才发 |

## 4. core 只读接口清单（与事件并列的第二种跨模块手段）

| 接口 | 读什么 | 为什么不能走事件 |
|---|---|---|
| `IQiReader` | 玩家当前 `qi` / 境界 ordinal / 小境界段 | 面板与 DSL 求值需要**同步拉取**，事件只有变更时刻 |
| `IAmbientQiReader` | 坐标 → 环境系数（含缓存命中路径） | 速率计算每结算片都要问，不能靠缓存事件 |
| `IFlagReader` | `flagKey` → boolean | 对话 DSL 条件求值是纯函数，禁止副作用（03 §8） |
| `IReputationReader` | `factionId` → int | DSL 的 `reputation(fac >= n)` 谓词依赖 |

契约：接口方法**必须**是纯读，不得触发结算；返回值不得是 `StrifeData` 本体（否则等于把附件漏给别模块，违反 §1 规则 1）。

## 5. 每个事件的单测要求（03 §2 末条 + 07 A0-4）

1. 载荷完整性：post 前所有契约字段非默认值（`Objects.requireNonNull` 或显式哨兵，禁止"字段为 null 表示没算"）。
2. 订阅隔离：一个订阅者抛异常时，另一个订阅者的处理仍被观察到 —— 该结论**须先实测 NeoForge 总线行为再定断言**（§8 要点 2）。
3. 取消语义：可取消事件在"已取消"状态下，core 的写回点必须观察到 `isCanceled()` 并跳过写入（`FlagChangedEvent`、`ReputationChangedEvent` 两条各有正反用例）。
4. 幂等：同一逻辑结果重复 post（重连补算、任务重复交付）时，订阅方不得双份推进——QuestEngine 侧用 `uuid + questId + progressHash`（03 §4）。
5. 频率：时间片结算类（`QiChangedEvent`）须断言"N tick 内至多 1 次"，直接守 03 §6 红线。

## 6. 与网络同步的边界

- 事件 = **服务端进程内**的解耦手段，绝不等同于 S2C 包。面板数据同步走 03 §5 的 delta 合并通道，静止时单玩家 ≤5 包/s。
- 订阅者若要把事件结果推给客户端，只能标脏（dirty flag），由 tick 末统一合并；**禁止在订阅者内直接发网络包**（否则一次突破可能发三帧重复包）。

## 7. 落码指引（供 A 粘贴的 Javadoc 成稿两例）

包位置：`com.strife.core.event`（core 是禁区，以下按 03 §2"core 声明 + Javadoc 契约"提供文本，不由 Agent 提交）。

```java
package com.strife.core.event;

import net.minecraft.server.level.ServerPlayer;
import net.neoforged.bus.api.Event;

/**
 * 修为变更后签发（03 分册 §2 跨模块通信唯一入口之一）。
 *
 * <p><b>服务端权威</b>：只在服务端 post，载荷一律取服务端结算结果，绝不接受客户端上报值（03 §4）。
 * 客户端看到的是 S2C 同步通道里的快照，不是本事件（03 §5）。
 *
 * <p><b>不可取消</b>：结果已签发，订阅方只能反应、不能否决；否则服务端与面板必然不一致。
 *
 * <p><b>频率</b>：打坐走时间片结算（NUMBERS.md {@code sit:tick_interval_ticks}），一次结算至多一次
 * 本事件；单玩家附加逻辑 ≤0.05ms/tick 的红线由"降频 + 不发每刻事件"共同守住（03 §6）。
 *
 * <p><b>载荷契约</b>：{@code source} 只能是 {@code sit|pill|quest|breakthrough|refund} 之一
 * （05 分册 §5 锁定的三种获取渠道 + 两项回退）；新增取值 = 契约变更，须 ADR。
 *
 * <p>订阅方：quest（进度推进）、client_fx 同步层（标脏，不得直接发包）。
 */
public class QiChangedEvent extends Event {

    /** 变更发生的玩家；恒为非 null 的服务端玩家对象。 */
    public final ServerPlayer player;

    /** 变更前的修为（{@code StrifeData.qi}）。 */
    public final int oldQi;

    /** 变更后的修为，已由服务端裁剪到境界上限内。 */
    public final int newQi;

    /** 变更来源，取值见 {@link #SOURCE_VALUES}。 */
    public final String source;

    /** 契约允许的来源取值，供单测与 Validator 复用。 */
    public static final java.util.Set<String> SOURCE_VALUES =
            java.util.Set.of("sit", "pill", "quest", "breakthrough", "refund");
}
```

## 8. 会签要点（B 逐条回答后 A0-4 才算准出）

1. §3 的九个事件够不够 M1–M3 用？特别是**采集类目标**：本期靠原版破坏事件 + `FlagChangedEvent` 覆盖，还是必须补一个 `ItemCollectedEvent`（补了就得回答"为什么不直接订阅原版 + 归属判定"）。
2. NeoForge 21.1 游戏总线对"订阅者抛异常"的真实行为是什么（吞掉并继续 / 中断后续订阅者）？**未验证**——§5 用例 2 的断言方向取决于它，须落码时实测。
3. §2 的重入深度上限 8 是否合理（与对话 DSL 的 1000 步求值上限是否要统一成一个口径）。
4. `FlagChangedEvent` 的 `long` bitset 只有 64 位：H3 因果/仇杀记录表用不了 bitset（它是记录而非标记），是否在本目录就写清"flag ≠ 因果记录"，避免 M4 误用。
5. 本文引用的第三方类名以缓存 jar 条目清单核对：`bus-8.0.5.jar` 含 `net/neoforged/bus/api/{Event,ICancellableEvent,EventPriority,IEventBus}.class`；`neoforge-21.1.251-universal.jar` 含 `event/entity/living/LivingDeathEvent`、`event/entity/player/PlayerEvent$Clone`、`event/level/LevelEvent`、`event/server/ServerStartedEvent`、`attachment/AttachmentType`。**方法层面的行为（谁在何时 post、取消传播）未逐一验证**，落码前须以官方文档或实测复核（AGENTS：引用第三方行为必须给出处）。
