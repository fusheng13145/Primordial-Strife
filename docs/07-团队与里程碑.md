# 07 团队与里程碑

## 1. 团队构成（4 人实名：2 名有开发经验 + 2 名无开发经验，全员配 AI Agent，D2/ADR-003）

| 成员 | 背景 | 角色 | 主责 | 权限分区 |
|---|---|---|---|---|
| **A** | 有开发经验 | **TL / 服务端主程**（兼 QA 门禁） | core、realm 逻辑；架构与 ADR 裁决；CI/发布门禁；所有禁区的唯一写权与合并权 | 禁区 + 开区(工具) |
| **B** | 有开发经验 | **DEV / 玩法与客户端** | combat、production、world、client_fx；网络同步与性能；灰区 Review owner | 灰区 + 开区 |
| **C** | 无开发经验 | **DES / 内容制作人** | NUMBERS/STORY/LORE 真相源维护与**名义确认人**；tables 填表；AI 文本/美术流水线运营；手工用例执行 | 真相源 + 开区 |
| **D** | 无开发经验，**M4 前不加入** | **资料与社区**（低优先级任务池，§8） | 竞品调研、LORE 巡检、翻译复核、用例执行备份、资产台账 | 开区 |

规则：
- A/B 的切分线**就是**手册的禁区/灰区边界——出了问题不需要讨论责任归属。
- 真相源"人名义确认"默认由 C 执行；破档级、数值区间级变更需 C+A 双确认。
- owner 缺席时决策顺延 A，不允许"先改了再说"。
- AI Agent 按 06 分册挂在各成员名下工作，**Agent 不占人力编制、不算工期余量**——排期按人的有效工时估，Agent 是缓冲。
- C/D 的产出物一律是"表/文本/报告/台账"，永远不进 Java 代码路径；两人在 06 分册中按"开区+真相源"授权，无灰区权限。

## 2. 现实排期原则（针对小团队 + AI）

- 周期按**周**计，但每里程碑只锁"准出条件"不锁"功能清单细节"：准出条件是合同，清单是手段。
- 砍范围顺序：先砍世界系统（M4 可推迟）→ 再砍表现（M5 可缩）→ 内容管线与 realm 主链**永不砍**。
- 每周一次 30 分钟同步：过风险登记册（08 分册）+ Agent 工单看板，只回答"哪里在骗我们"（CI 绿但没真跑的用例、占位没清点、表格与产物漂移）。

## 4. MVP 验收用例（W3 起每里程碑回归）

```
创建角色 → 打坐 → 攒满修为 → 突破到筑基 → 接第一个主线 → 交付 → 拿到奖励
→ 重载存档 ×3 数据一致 → 断线重连修为不丢 → 死亡不掉修为但掉灵石
```

手工用例矩阵按 01 分册成功标准展开，每行记录：步骤、期望、实际、证据（日志/录像/CI 链接）。无证据的"通过"不算通过（06 分册 §4）。

## 5. 发布矩阵

| 制品 | 内容 | 用途 |
|---|---|---|
| `strife-X.Y.Z.jar` | 全量包（平台 + 内置 content-base） | CurseForge/Modrinth 主发布 |
| `strife-server-X.Y.Z.jar` | 去 client_fx 的纯净服务端 | 专用服务端 |
| `content-base-X.Y.Z.zip` | 可独立替换内容包 | 整合包作者、热更内容 |

版本语义：X=内容格式大版本（破档才 +1）、Y=里程碑功能、Z=平衡/修复。Beta 标注联机为实验性（D3）。

## 6. 内容产能演练（固定动作，代号"W4 演练"）

"W4"是固定动作代号（与周编号无关），分两阶段执行：

1. **断链校验（M3 末，进 M3 准出）**：在表中故意留一处悬空引用 → Validator 必须拦截、构建必须红。验证的是门禁本身。
2. **全量产能演练（M4 期间）**：由 DES + 一个 Agent 在**零逻辑改动**前提下 3 天内产出一章 playable 内容（任务 DAG + 对话 + 奖励 + 文本）。这次演练的耗时就是"新增一章"的对外承诺数字。
