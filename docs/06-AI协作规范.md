# 06 AI 协作规范

> 本项目默认"人 + Agent"混合开发。本章把"谁能改什么、怎么验收"写成硬规则，对每一个 Agent 会话同等生效。仓库根目录 `AGENTS.md` 是本分册的投影，两者冲突以本分册为准。

## 1. 权限分区（Agent 开工前必查）

| 分区 | 路径 | Agent 权限 | 人的动作 |
|---|---|---|---|
| **禁区** | `mod/platform/**/core/`、`mod/platform/**/realm/` 逻辑代码 | 只读。允许出**方案文档与补丁建议**，不许直接提交可合并变更 | 成员 A（TL）编写，Agent 仅做测试/文档/格式化 |
| **灰区** | combat / production / quest / world 包 | 可写：新文件、Bug 修复、测试；**改既有公共签名/事件契约须先出 ADR 草案** | 成员 B（DEV）逐行 Review + 跑对应单测后合并 |
| **开区** | `content-base/`、`tables/`、`tools/datagen`、`tools/validator`、测试代码、docs、CI 配置、占位资产 | 直接生产，走 CI 门禁即可合并（每日抽查） | 抽检 + Validator 说了算 |
| **真相源** | `content/NUMBERS.md`、`STORY.md`、`JSON_SCHEMA.md`、`LORE.md` | Agent 可起草整版，**合入必须人名义确认**（commit author 是人）；默认确认人为成员 C（DES），破档级/数值区间级变更 C+A 双确认 | 详见 07 §1 |

判定冲突时按"最严格分区"处理。`buildSrc` 依赖断言与 CODEOWNERS 强制本表，不依赖自觉。

## 2. 角色与 Agent 的关系（详见 07 分册分工）

- 人负责：**决策、契约、审核、合并、担责**。
- Agent 负责：探索、实现草案、填表、生成文本/占位资产、写测试、跑验证。
- 每个 Agent 任务必须挂在一个人类 owner 名下；没有 owner 的 Agent 产出不予合并。

## 3. 任务派发模板（Agent 工单）

```markdown
## 任务：<编号> <一句话目标>
分区：开区|灰区|禁区(只读)        Owner：<人名>
上下文包：<必读文件清单：手册分册§、真相源§、相关源码路径>
约束：不得修改<文件/签名清单>；数值只从<table/NUMBERS §x>读取
验收：<具体命令：./gradlew spotlessCheck build test validator（或子集如 :tools:validator:run）、测试名、手工用例编号>
交付物：<diff 范围 + 自检报告>
```

上下文包规则：宁可给多给准，不要让 Agent 猜。涉及跨模块行为时，附上 03 分册相关小节原文，而不是让它"自行探索仓库"。

## 4. 验收链（Agent 产出 → 合入的唯一路径）

```
Agent 自检（./gradlew spotlessCheck build test validator，全绿才允许交单）
→ CI 门禁（04 分册 §8，红 = 直接打回，不需要人看）
→ Owner Review（灰区以上逐行；开区 diff 抽查 + 看 CI 报告）
→ 合并后 Owner 本地跑关键手工用例（MVP 链路涉及的必须跑）
```

- **人不跑验证、只看 Agent 的"我测试过了"= 无效验收**。Agent 报告里的"测试通过"必须能在 CI 记录或本地复跑中找到对应证据（evidence-guard 原则：结论必须挂证据，无证据的 API/库行为先查证再采用）。
- Agent 声称"该库支持 X"而手册/官方文档未被引用证实 → Review 时按未验证处理。

## 5. 幻觉与范围蔓延防线

| 风险 | 规则 |
|---|---|
| 编造 API | 引用任何第三方库行为必须给出来源（官方文档链接/仓库版本 tag/手册小节）；写不出的按未验证驳回 |
| 越界重构 | "顺手清理"不在工单范围内的一律还原；确有必要另开工单 |
| 范围蔓延 | 单月内新增 ≥3 个"顺便做一下"的系统即触发 R6 熔断：回归 01 分册不做清单，新系统必须 ADR |
| 大提交 | 单 PR >400 行逻辑代码（不含生成物/文本）必须拆分，否则驳回 |
| 假绿测试 | 测试必须在能触发对应逻辑的位置有断言；只 assert(true) 的空测试按事故处理 |

## 6. 双真相源防护

文档、代码注释、工单描述里的数值/ID/字段名都是**引用**，不是定义。Agent 修正引用时禁止"根据代码更新真相源"方向的逆向同步——真相源永远由人裁决。

## 7. AGENTS.md 骨架（放仓库根，投影自本分册）

```markdown
# AGENTS.md — 玄黄劫争 (Primordial Strife，技术代号 strife)
- 唯一参照：docs/ 手册。开工先读 docs/README.md 与任务指定分册。
- 权限分区见 docs/06。core/、realm/ 逻辑禁改（只出方案）。
- 数值/字段/剧情：只改 content/ 真相源并走人审；JSON 产物禁止手改（@generated）。
- 服务端权威：不得信任客户端上报；跨模块只走事件/core 接口。
- 交单前必跑：./gradlew spotlessCheck build test validator —— 全绿才交，附命令输出。
- 禁止顺手重构、禁止编造 API（引用给出处）、单 PR 逻辑代码 ≤400 行。
- 结论与猜测分开写；未验证项显式标注。
```

## 8. Agent 适用任务清单（沉淀可复制的派发模式）

- 内容：填表、生成 lang、起草对话节点（带 LORE 上下文包）、DataGen 模板维护、Validator 报错修复。
- 工程：单测补写（quest DAG 100%）、spotless 修复、依赖升级试验（分支验证报告）、性能采样脚本。
- 表现：占位贴图生成、粒子参数调优（禁改渲染管线）、Patchouli 条目排版。
- 禁止：core/realm 逻辑实现、破档操作、改 CI 门禁"让它变绿"、删测试/删断言。
