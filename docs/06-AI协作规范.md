# 06 单人开发与 AI 协作规范

> 本项目采用**单人独立开发 + AI Agent**模式（ADR-024）。本册把"本人能改什么、Agent 能改什么、怎么验收"写成硬规则，对每一个 Agent 会话同等生效。仓库根目录 `AGENTS.md` 是本分册的投影，冲突以本分册为准。
>
> 历史文档中的 A/B/C/D 是已废止的四人分工称谓；自 ADR-024 起，所有决策、实现、审核与真相源确认统一归**本人**。

## 1. 决策权与工作模式

| 角色 | 职责 | 边界 |
|---|---|---|
| **本人** | 决策、实现、审核、合并、发布、真相源确认 | 唯一有权改 core/realm 逻辑、拍板 ADR、关闭门禁、确认 `content/` 四份真相源 |
| **AI Agent** | 探索、起草、实现灰区/开区改动、写测试、填表、生成文本与占位资产、跑验证、整理文档 | 产出默认"未验收"；不得自批、不得代本人确认真相源、不得改门禁让它变绿 |

- 本人负责"做对的事"，Agent 负责"把事做快"；两者都不豁免证据要求。
- 每个 Agent 任务必须由本人发起并验收；没有发起人的 Agent 产出不予合并。
- 单人开发没有第二个人类复核，用 §4 的四道防线替代（红先测试、全新上下文复核、外部门禁、实机证据）。

## 2. 权限分区（Agent 开工前必查）

| 分区 | 路径 | Agent 权限 | 本人动作 |
|---|---|---|---|
| **禁区** | `mod/platform/**/core/`、`mod/platform/**/realm/` 逻辑代码 | 只读。允许出**方案文档与补丁建议**，不许直接提交可合并变更 | 本人编写与合并；Agent 仅做测试/文档/格式化 |
| **灰区** | combat / production / quest / world 包 | 可写：新文件、Bug 修复、测试；**改既有公共签名/事件契约须先出 ADR 草案** | 本人逐行 Review + 跑对应单测后合并 |
| **开区** | `content-base/`、`tables/`、`tools/datagen`、`tools/validator`、测试代码、docs、CI 配置、占位资产 | 直接生产，走 CI 门禁即可合并 | 抽检 + Validator 说了算 |
| **真相源** | `content/NUMBERS.md`、`STORY.md`、`JSON_SCHEMA.md`、`LORE.md` | Agent 可起草整版，**合入必须本人确认**（commit author 是本人） | 逐项拍板 `[拟]` / `[占位]`；破档项与数值区间逐条签字 |
| **构建门禁** | `buildSrc/`、`.github/workflows/`、Validator 规则 | 仅在本人明确派发时修改；**永远不得为了让当前改动变绿而放宽门禁** | 本人复核并记录理由 |

判定冲突时按"最严格分区"处理。`buildSrc` 依赖断言、Validator 与 CI 强制本表，不依赖自觉。

## 3. 任务派发模板（Agent 工单）

```markdown
## 任务：<编号> <一句话目标>
分区：开区|灰区|禁区(只读)        执行者：本人|Agent
上下文包：<必读文件清单：手册分册§、真相源§、相关源码路径>
约束：不得修改<文件/签名清单>；数值只从<table/NUMBERS §x>读取
验收：<具体命令：./gradlew spotlessCheck build test validator（或子集）、测试名、手工用例编号>
证据：<命令输出路径 / 测试报告 / 截图 / 待验证台账条目>
交付物：<diff 范围 + 自检报告>
```

上下文包规则：宁多勿少，不要让 Agent 猜。涉及跨模块行为时，附上 03 分册相关小节原文，而不是让它"自行探索仓库"。

## 4. 验收链（Agent 产出入库的唯一路径）

```
Agent 自检（./gradlew spotlessCheck build test validator，全绿才允许交单）
→ CI 门禁（04 分册 §8，红 = 直接打回，不需要人看）
→ 本人 Review（灰区以上逐行；开区 diff 抽查 + 看 CI 报告）
→ 本人实机用例（MVP 链路与玩家可见行为必须跑）
→ 更新 10 册快照与待验证台账
```

四道替代复核：

1. **红先测试**：行为改动必须先有失败测试；失败原因必须是功能缺失，不是编译错误。
2. **全新上下文复核**：高风险改动（core/realm、公共契约、破档、门禁）派一个**没有实现上下文**的 Agent 只读复核 diff 与规格，专找假绿、越界与未验证断言。
3. **外部门禁**：CI + Validator + 模块依赖断言 + 纯净 jar 冒烟；门禁红就是红。
4. **实机证据**：游戏内行为必须有本人操作记录；Agent 不得自证。

- **评审路由**：`.github/CODEOWNERS` 全部路径指向本人，仅用于变更提醒；单人模式不把"作者以外的批准"设为合并门槛，评审责任由上述四道防线承担。
- **本人不跑验证、只看 Agent 的"我测试过了"= 无效验收**。Agent 报告里的"测试通过"必须能在 CI 记录或本地复跑中找到对应证据（evidence-guard：结论必须挂证据）。
- Agent 声称"该库支持 X"而手册/官方文档未被引用证实 → 按未验证处理。
- 复核结论写进 PR 描述或 10 册；"我看过了"不算证据。

## 5. 幻觉与范围蔓延防线

| 风险 | 规则 |
|---|---|
| 编造 API | 引用任何第三方库行为必须给出来源（官方文档链接/仓库版本 tag/手册小节）；写不出的按未验证驳回 |
| 越界重构 | "顺手清理"不在工单范围内的一律还原；确有必要另开工单 |
| 范围蔓延 | 单月内新增 ≥3 个"顺便做一下"的系统即触发 R6 熔断：回归 01 分册不做清单，新系统必须 ADR |
| 大提交 | 单 PR >400 行逻辑代码（不含生成物/文本）必须拆分；同一交付链例外须在 PR 描述列文件与耦合理由（D-P0-4，2026-10-25 已裁决） |
| 假绿测试 | 测试必须在能触发对应逻辑的位置有断言；只 assert(true) 的空测试按事故处理 |
| 自批 | Agent 不得批准自己的产出；本人未复核的 Agent 产出不得标"已完成" |

## 6. 双真相源防护

文档、代码注释、工单描述里的数值/ID/字段名都是**引用**，不是定义。Agent 修正引用时禁止"根据代码更新真相源"方向的逆向同步——真相源永远由本人裁决。

- 改数值/字段/剧情：先改 `content/`，再跑 DataGen + Validator，最后同步文档。
- 发现代码与真相源冲突：以真相源为准修代码；若真相源确实错了，由本人改真相源并写明理由。
- 旧草案、聊天记录、口头约定不得作为依据（R10）。

## 7. 每批交单自审清单

- [ ] 改动只覆盖工单范围，没有顺手重构
- [ ] 新增/修改行为有红先测试，且测试能在实现回退时变红
- [ ] 没有受管数值字面量；数值来自 NUMBERS 或 DataGen 产物
- [ ] `@generated` 产物由 DataGen 生成，与源表同提交
- [ ] `spotlessCheck build test validator` 全绿；中文路径下测试已在 ASCII worktree 复跑
- [ ] 公共签名/事件契约变更已附 ADR 草案
- [ ] 文档引用已同步（10 册快照、待验证台账、相关分册）
- [ ] 未验证项已显式标注，没有把"未验证"写成"已完成"
- [ ] 没有删测试/删断言/放宽门禁
- [ ] 提交信息符合 Conventional Commits，单 PR 逻辑代码 ≤400 行或已说明交付链例外

## 8. AGENTS.md 骨架（放仓库根，投影自本分册）

```markdown
# AGENTS.md — 玄黄劫争 (Primordial Strife，技术代号 strife)
- 唯一参照：docs/ 手册。开工先读 docs/README.md 与任务指定分册。
- 开发模式：单人 + AI Agent（docs/08 ADR-024）。决策、审核、真相源确认归本人。
- 权限分区见 docs/06。core/、realm/ 逻辑 Agent 禁改（只出方案），本人可直接写。
- 数值/字段/剧情：只改 content/ 真相源并走本人确认；JSON 产物禁止手改（@generated）。
- 服务端权威：不得信任客户端上报；跨模块只走事件/core 接口。
- 交单前必跑：./gradlew spotlessCheck build test validator —— 全绿才交，附命令输出。
- 未经本人明确同意，Agent 不得启动游戏；待验证项记入 deliverables/待验证台账.md。
- 禁止顺手重构、禁止编造 API（引用给出处）、单 PR 逻辑代码 ≤400 行。
- 结论与猜测分开写；未验证项显式标注。
```

## 9. Agent 适用任务清单（沉淀可复制的派发模式）

- 内容：填表、生成 lang、起草对话节点（带 LORE 上下文包）、DataGen 模板维护、Validator 报错修复。
- 工程：单测补写、spotless 修复、依赖升级试验（分支验证报告）、性能采样脚本、全新上下文只读复核。
- 表现：占位贴图生成、粒子参数调优（禁改渲染管线）、手册条目排版。
- 文档：10 册快照整理、索引与链接校验、历史草案标注。
- 禁止：core/realm 逻辑实现、破档操作、改 CI 门禁"让它变绿"、删测试/删断言、代本人确认真相源。
