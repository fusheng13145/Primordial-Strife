# 04 内容管线（content-base）

## 1. 数据流总览

```
tables/*.csv + content/NUMBERS.md + content/STORY.md     ← 唯一编辑入口（Agent 起草、本人审定）
        │  DataGen（:tools:datagen）
        ▼
content-base/src/main/resources/data|assets/strife/...   ← 生成产物，带 @generated 头，禁止手改
        │  Validator（:tools:validator，PR 门禁 + 每晚全量）
        ▼
构建进 jar / 导出 content-base-X.Y.Z.zip（可独立替换）
```

唯一规则：**生成产物永远不被手工编辑**；产物与源表不一致 → 重新生成并回溯原因。

## 2. 内容目录与关键字段

| 目录（data/strife/ 下） | 内容 | 关键字段 | 来源 |
|---|---|---|---|
| strife_realms | 境界定义 | qi_max / lifespan / unlocks / breakthrough_success_key | NUMBERS `@@realms` 直出 + `rules.json` 运行时表 |
| strife_techniques | 功法 | passives / qi_rate / required_realm / required_spiritroot / faction | `techniques.csv` |
| strife_spells | 法术 | projectile / cost / cooldown / damage_formula_key | `spells.csv` |
| strife_pills | 丹方 | pattern / core_slot / heat_range / outputs（含概率） | `pills.csv` |
| strife_artifacts | 器图（炼器） | blank / restriction_count（禁制数） / core_slot / outputs（含品质概率） / active_skill | `artifacts.csv`（配方机+主动技能+耐久/修复已接；属性/被动=G-1） |
| strife_quests | 任务 DAG（一章一文件） | prerequisites / objectives / rewards / timer / fail_goto | `quests_<章>.csv` |
| dialog_trees | 对话树（一章一文件） | nodes / conditions(DSL) / next / text_key | `dialog_trees_<章>.csv` |
| dialog_text | 对话正文（服务端权威文本通道） | texts | `dialog_<章>_text.csv` |
| strife_factions | 势力 | attitude 矩阵 | `factions.csv` |
| strife_worldgen | 灵气场与矿石运行时参数 | ambient_* / ore_drop_weights / herb_grass_drop_prob | NUMBERS `@@world` 直出 `rules.json` + `ores.csv`（一行 5 产物，G-7 收口） |
| strife_spirit_field | 区域灵气场 | region_id / ambient_qi_ratio | `spirit_field.csv`（W4 P3） |
| strife_core / strife_combat | 各自运行时数值表 | 限速 / 伤害 / 冷却 | NUMBERS 直出 |
| strife_periods | 周期事件声明（H5） | kind / period_ticks / condition / effect_on_world | `periods.csv`（W4 P3） |
| strife_wars | 声明式冲突（H7） | belligerents / cause_predicate / phases / form | `wars.csv`（W4 P3） |
| strife_places | 地点（G-4 导航 + 灵气地点差异化） | dimension / x,y,z / radius / qi_scale | `places.csv` |
| strife_npcs | 世界内 NPC 摆放 | dimension / place / x,z（y 取运行时地表高度） | `npcs.csv` |
| dimension / dimension_type | 上界维度 | generator_type / noise_settings / coordinate_scale / ambient_light | `dimensions.csv`（ADR-021） |
| worldgen/biome | 群系 | sky_color / fog_color / water_color / features | `biomes.csv`（ADR-021） |
| worldgen/structure + structure_set | 宗门结构 | kind / biomes / step / spacing / separation | `structures.csv`（ADR-022） |
| worldgen/configured_feature + placed_feature | 上界装饰 | block / replace_target / veins_per_chunk / vein_size | `realm_decor.csv`（ADR-021） |
| loot_table | 掉落表 | 与任务奖励联动，走原版 loot table 格式 | `ores.csv` + `BeastLootGenerator` |
| lang | zh_cn / en_us | key 与内容 ID 同源 | 手写种子 + DataGen 键对齐校验 |

MVP 只填 realms/techniques/spells/pills/artifacts/quests/dialog_trees 与序章 lang；符箓/阵法/灵植在 EP0 仅占位不填（09 分册 F，玩法归 EP1）。

`tables/` 下 CSV 填了行但未注册生成器 → `DataGenMain` 直接报错并指名这张表，不静默丢弃；填了行、有生成器但产物缺失 → V-FRESH 拦下。

字段级契约以 `content/JSON_SCHEMA.md` 为准；表结构变更 = 改 SCHEMA + DataGen + Validator 三处同一 PR。

## 3. 章节交付单元

每章交付 = **任务 DAG + 对话树 + 奖励/掉落表 + 新增内容资产 + zh_cn 文本（en_us 占位）**，五件套缺一即章未完成。序章目标 45 分钟通关、M3 交付全部节点；第一章主题待 STORY.md 定稿（第二章主题"五行灵珠"）。

## 4. ID 与命名规范

- 格式 `<域>_<章>_<语义>` 全小写下划线（示例 `ch2_pearl_water`、`tech_qingxin_jue`、`quest_prologue_meditation_01`）；域前缀枚举：`tech_ / spell_ / pill_ / qi_ / quest_ / dlg_ / npc_ / block_ / item_ / ch<N>_`。
- **lang key 与内容 ID 一一映射**：每个内容 ID 必须有 `item.strife.<id>` 等对应 key，zh_cn 缺失即构建失败（D4：en_us 先以占位串过 CI）。
- 重命名 ID 视同破档：须 ADR，且保留旧 ID 迁移映射一个主版本。
- 完整用词与目录规则见 [11 命名与目录规范](11-命名与目录规范.md)。

## 5. DataGen 规范

- 输入：CSV 表（UTF-8、首行表头、注释列以 `_` 开头）、NUMBERS.md 数值块（解析约定见 05 §1）、STORY.md 大纲（仅任务骨架生成用）。
- 输出：确定性排序（同输入必同产物，diff 可读）；文件头注入 `@generated from tables/xxx.csv` + 源表哈希。
- 附属产物 `data/strife/strife_index.json` 列出本次写出的全部产物路径；注册期早于 datapack 加载的运行时表（法术/丹方）只读索引，故"表里加一行"即可让内容可达，不再维护手写路径清单。
- 运行 `./gradlew :tools:datagen:run`，本地与 CI 均跑；产物 diff 未提交视为 CI 失败（"生成器漂移"检查）。
- DataGen 代码属开区（06 §2），Agent 可直接维护。

## 6. Validator 校验项（全部构建期，PR 必过）

校验面如下（V-RANGE 含多个子项）；当前 **16 项**，判据：`./gradlew :tools:validator:run` 输出 `json-files=151 csv-files=37 checks=16 problems=0`（2026-11-06 实测）。

| 检查 | 内容 |
|---|---|
| V-DUP 重复 ID | 全域唯一；台账表（首列非内容 ID）与对话文本配对表显式豁免 |
| V-FRESH 产物新鲜 | `@generated` 头哈希与当前源表一致（含 `content/` 真相源派生域）；内容索引由 V-INDEX 独立把关 |
| V-INDEX 内容索引 | `strife_index.json` 与全部 `@generated` 产物一一对应：漏列 = 产物进了 jar 但运行时不可达，多列 = 陈旧索引 |
| V-DAG 连通 | 任务图无环、从章节入口可达全部必做节点、奖励闭环 |
| V-REF 一期 | 跨表引用不得悬空（材料/产出/法术/前置任务/lang key） |
| V-REF 二期 | 源表主键 / lang item 键与 `npc.strife.<id>` / LORE NPC 卡存在性；NPC 摆放另查地点存在、维度一致、坐标落在半径内、对话树存在（占位符走白名单） |
| V-GROWTH 成长比 | 查 NUMBERS 区间表：成长比 1.8–2.5、成功率 0–1、寿元单调递增 |
| V-RANGE 数值域 | 真相源数值区间越界；H1 价格字段非负 |
| V-RANGE 灵气场域 | `strife_spirit_field` 的 `ambient_qi_ratio` 落在 `world:ambient_qi_min..max` 且 ≠ 0 |
| V-RANGE 周期域 | `strife_periods` 的 `kind` 枚举合法 |
| V-PROB 概率归一 | 丹方/掉落 outputs 概率和 = 1（容差 1e-6） |
| V-TEXT 文本缺项 | zh_cn 全覆盖；en_us 允许占位但不得为空串（对话域显式豁免） |
| V-DSL 合法 | 对话条件表达式词法/括号/谓词白名单/effects args 正则；独立词法校验器 `DslSyntax` |
| V-NAME 命名规范 | ID 用拼音、文本用中文（11 分册）：ID 形状 `[a-z][a-z0-9]*(_[a-z0-9]+)*`、禁中文 ID（会崩）、lang key 三段式、zh_cn 值必含汉字；源表与产物两侧同查，台账表只查非 ASCII 字母 |
| V-FMT 格式契约 | `content_format` 落在平台 jar 支持区间；严格域未知字段报错（JSON_SCHEMA §1.2 规则 2，2026-11-01 转正） |
| V-DRIFT 键漂移 | `_key` 与展开值一致（JSON_SCHEMA §3 末，防手填漂移，2026-11-01 转正） |
| V-BIOME 群系有效 | 产物中任何 `biomes` 字段（biome_modifier / spawn 等）不得引用 1.18 已删除的群系 ID（`minecraft:mountains` 等会在注册期直接崩，2026-11-04 RCON 冒烟抓获） |

报错必须给出**文件路径 + JSON pointer + 人话说明**（Agent 能否自助修复的关键，06 分册）。`content/NUMBERS.md` 缺席时，真相源侧 V-GROWTH / V-RANGE 自动跳过并在输出中声明，不静默通过。

## 8. CI 门禁清单（PR 必过）

```
spotlessCheck → build → unitTest（realm/quest 单测 100% DAG 用例）
→ datagen 新鲜度 → validator 全项 → 模块依赖断言 → server jar headless 冒烟 → 附件内存快照测试
```

每晚追加：性能基准（tick 采样、灵气场 chunk 生成耗时）、蒙特卡洛 10 万次丹方期望抽样、纯净 jar 2 小时长跑冒烟（M5 起）。

"看起来绿其实没跑"的两种形态，CI 必须显式防住：

- **buildSrc 的测试不会被主构建执行**（主构建只编译它）：模块依赖断言用例 `ModuleDependencyRulesTest` 必须靠 `./gradlew -p buildSrc test` 显式触发。
- **单测执行要有计数断言**：`build` 绿与"某模块测试被静默跳过（NO-SOURCE / 缺 junit engine）"并不矛盾。CI 末尾对 buildSrc / platform / tools:validator / tools:datagen 各断言 ≥1 用例，逐模块计数写进 step summary。

## 9. 内容热更新

- `content-base-X.Y.Z.zip` 可被整合包作者独立替换；加载顺序：内置内容 → 外部内容包覆盖（同 ID 覆盖须在 Validator 白名单内，防误伤）。
- 平台 jar 声明 `contentFormatVersion`，内容包标注自身版本，不匹配只警告不崩溃（兼容一个区间）。
