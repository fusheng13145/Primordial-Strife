# 03 架构与模块

## 1. 模块职责一览

| 包 | 职责 | 禁区说明 |
|---|---|---|
| core | 注册管线、自定义事件定义、Attachments/数据层框架、网络框架、命令框架、配置 | **逻辑禁区**（06 分册） |
| realm | 灵根生成、打坐、修为、突破、渡劫结算、寿元、面板数据源 | **逻辑禁区** |
| combat | 功法（被动/主动）、法术实体与弹道、法宝激活、妖兽 AI | 灰区 |
| production | 统一配方机（丹/器/符/阵/种五类共用一套框架）、品质阶结算 | 灰区 |
| quest | QuestEngine（DAG、事件驱动进度、导航）、对话树 DSL 解释器 | 灰区 |
| world | 灵气浓度场（区域环境系数）、矿石 placement、宗门结构、上界维度 | 灰区 |
| client_fx | 修炼面板、施法轮盘、粒子音效、Patchouli、调试叠加层 | 开区（仅客户端） |

MVP 阶段（M0–M3）production 只交付炼丹与炼器两类，其余三类接口预留、表不填。

## 2. 模块依赖规则（CI 强制）

允许的直接依赖只有一条链，**其余跨模块访问一律走事件或 core 定义的接口**：

```
client_fx → (S2C 协议，不直接依赖任何逻辑包)
combat / production / quest / world → realm → core
禁止：realm → 任何其他包；任何包 → combat/production/quest/world（横向依赖）
```

- 跨模块通信只用两种手段：**NeoForge 事件总线 + core 自定义事件**（如 `PlayerBreakthroughEvent`、`EntityKilledByPlayerEvent`），或 core 中的只读接口（如 `IQiReader`）。
- 出现"模块 B 直接读写模块 A 的 Attachment"即视为架构违规，立即重构为事件（风险登记 R5）。
- 依赖图由 `buildSrc` 中的 ArchUnit 式断言在 CI 校验，违规构建失败。
- 新增自定义事件 = 在 core 声明 + 附 Javadoc 说明载荷契约 + 单测。

### 2.1 原语与剧本分离（低耦合总原则，ADR-016）

本项目世界观定位是**高自由度修仙大世界**（宗门/散修择路、人妖大战等主线战争、宗门对立），且早期功能形态大概率演化（如"人妖大战"可能从一次性主线变为周期活动）。因此：

- **平台代码只做"原语"**：事件、状态机、调度器、关系图、结算器——不写具体剧本。
- **剧本全部进内容表**：谁打谁、何时打、打输了怎样——都是数据声明，由原语解释执行。改玩法=改表，不改代码。
- 任何"把某个剧情事件直接硬编码进模块"的 PR 视为架构违规；确需新原语 → 事件/接口契约变更 → ADR。
- 早期实现的每个系统交付时须回答评审问题："**它变形时（主线→周期活动、单宗门→多宗门对抗）需要改代码吗？**"需要，则拆到原语/表两层为止。

## 3. 数据层（Attachments）

- 玩家数据用 NeoForge `AttachmentType` 挂在 Player 上；世界级数据（灵气场缓存、宗门状态）存 `SavedData`。
- 序列化格式：自定义 Codec，存档字段带 `CURRENT_DATA_VERSION`；**新增字段必须带默认值，删除字段保留 reader 兼容一个主版本；破档 = 主版本号 +1**（这是存档兼容红线）。
- 内存预算：单玩家全部附件 ≤2KB。手段：flags 用 long bitset；枚举存 ordinal（配合数据版本迁移）；不存可由查表还原的派生值（如"当前修炼速率"不入档，只入缓存）。
- 断线重连/重载一致性：所有附件走同一 `StrifeData` 聚合对象，`serialize/deserialize` 往返一致；MVP 用例"重载存档三次数据一致"即测此项。

## 4. 服务端权威与安全红线

**修为、灵气、任务完成、掉落、突破/渡劫结果全部由服务端计算签发。** 客户端只是显示器。

| C2S 意图包 | 服务端必做校验 | 限速（令牌桶） |
|---|---|---|
| 施法 | 冷却、灵气余额、境界/功法前置、目标距离 | ≤5 次/s |
| 打坐起止 | 状态机合法性（不能从"突破中"进"打坐"） | ≤2 次/s |
| 任务交互/交付 | DAG 前置、物品/条件真实满足、幂等键 | ≤2 次/s |
| 法宝主动使用 | 冷却、耐久、装备槽校验 | ≤5 次/s |

> 表内限速值为初始基线（示意）：**运行时真值以 NUMBERS.md 为准**（限速参数属 05 §1 收录范围），代码从 DataGen 产物读取。

- 幂等键：`uuid + questId + progressHash`，双人同时交付不双发。
- 管理命令（`/strife quest reset`、`/strife realm set` 等）仅 OP 可用，全部写审计日志（log 文件即可，不建数据库）。
- 任何"信任客户端上报数值"的代码在 Review 中直接驳回。

## 5. 网络同步（S2C）

- 变更合并 + delta 更新：附件脏标记 → tick 末合并 → 仅推送变化字段；静止时单玩家 ≤5 包/s。
- 单包 payload <32KB；超限（如任务 DAG 全量）必须分片或改拉取式（C2S 请求 → S2C 响应）。
- 面板类高频只读数据用独立 sync channel，不与事件包混道。

## 6. 性能红线（进 CI 性能基准，超标即构建红）

| 项 | 上限 | 实现手段 |
|---|---|---|
| 单玩家附加逻辑 | ≤0.05ms/tick | 打坐/灵气计算降频分桶（每秒 1–4 tick 一次），非每 tick |
| 单玩家附件内存 | ≤2KB | §3 约束 |
| 新区块灵气场生成 | ≤2ms/chunk（命中缓存 ≈0） | 区块生成期计算 + 区域粗粒度缓存（16x16 区块一值 + 细化层） |
| 同屏法术实体 | ≤64 | 对象池 + 超距回收 + 施法端拒绝 |
| 静止单玩家发包 | ≤5 包/s | §5 delta 合并 |
| 单网络包 | <32KB | §5 分片 |
| 法术端到端延迟 | <100ms（本地联机） | 意图包即时处理，不排队 |

打坐累计采用"时间片结算"：记录起止时间戳 + 环境快照，结算时一次性算，天然抗断线（重连补算），也避免每 tick 浮点累计。

## 7. 纯净服务端 jar

- 构建任务 `:platform:serverJar` 从产物中剔除 client_fx 包资源与入口注册，NeoForge 分侧 ModEntrypoint 保证服务端只加载 `server` 侧入口。
- **M0 起每个里程碑 CI 必须执行"纯净 jar 独立启动冒烟"**（headless 开服 60s 无异常），不是 M5 才做。
- client_fx 不得被任何逻辑包直接引用（依赖断言覆盖）。

## 8. 关键机制设计口径

- **灵根**：首次进服生成一次（seeded by 玩家 UUID + 世界 seed，服务端生成后入档，永不重算）；五行属性 + 品阶（凡/地/天/仙）→ 修炼系数、功法适配、法术威力（全部查表，05 分册）。
- **洗髓**：稀有道具触发重置灵根；重置后已学功法中不满足 `required` 条件的，客户端弹明确提示并置灰，**禁止静默失效**（数据层记录 `disabled_by` 原因）。
- **突破**：修为达上限 + 条件满足 → 服务端查表成功率 → RNG 结算。失败代价非破坏性（D6）：修为回退比例 + 材料损耗，不扣境界、不掉存档级资产。
- **渡劫**：高级突破附带天劫事件，实体与伤害全服务端；结果签发后广播。
- **寿元与大限**：境界提升增寿；寿元耗尽触发"大限"结算——修为大幅回退 + 强制进入虚弱状态（可恢复），不删角色（细则数值见 NUMBERS.md，O4 已拍板方向为 D6）。
- **任务进度**：完全事件驱动（击杀、采集、交付、境界变化都发事件），QuestEngine 订阅并推进 DAG；进度入档，断线重连不丢。任务物品支持末影箱内交付（扫描端特判）。
- **对话 DSL**：内置条件小语言（`realm>=练气3 && flag(ch1_met_elder) && item(灵石:10)`），解释器在 quest 包内，纯解释无副作用、有条件求值上限（防表写错死循环）。

## 9. 兜底与恢复

每个会"卡死玩家"的机制必须有 OP 兜底命令，命令框架在 core 统一注册：

```
/strife info                    查看当前玩家数据
/strife quest reset <id>        重置任务
/strife realm set <realm> <sub> 跳境界
/strife lifespan set <n>        调寿元（测试）
/strife balance reload          重载平衡数值（内容热重载，仅开发环境）
```

## 10. 扩展性钩子（ADR-012/016，M0 起生效）

世界完整度图谱见 09 分册。以下七个钩子是"现在不实现、但接口必须从 M0 就存在"的清单——每一条在 core 的成本 ≤1 天，后补的成本是破档级重构。**内容域本期不开发，只允许以钩子形态存在**。（EP 代号定义见 09 分册）

| # | 钩子 | 定义位置 | 未来解锁的内容 |
|---|---|---|---|
| H1 | **价格字段**：所有可交易内容的表结构含 `price`（灵石为统一货币单位），Validator 校验非负 | JSON_SCHEMA + DataGen | 灵石、坊市、拍卖、黑市（EP1） |
| H2 | **玩家势力声望向量**：`rep: Map<factionId, int[-100,100]>` + `affiliation: factionId \| none`（宗门弟子/散修身份），作为玩家数据的通用组件 | core/attachments | 宗门职级、世家、妖族、王朝、正魔阵营（EP1/EP3） |
| H3 | **因果/flag 图**：命名空间化世界标记（`<域>:<章>:<语义>`）+ 人物间债务/仇杀记录表（谁欠谁、谁杀谁） | core + quest | 恩仇结算、通缉令、心魔劫素材、突破因果阻碍（EP2） |
| H4 | **位面接口**：维度 ID 注册表 + "跨界迁移协议"（实体/附件数据的裁剪与映射规则），上界维度是其第一个消费者 | core/world | 灵界/仙界多级资料片零重构（EP4） |
| H5 | **全局时钟**：世界纪元计时器 + 周期事件调度器（开启/关闭窗口、频率、条件谓词均为表声明），灵脉潮汐先用它试跑 | SavedData in core | 秘境开启周期、灵气丰歉年、战争周期化（EP2/EP3） |
| H6 | **福缘入口**：掉落与事件抽取层预留 `luck` modifier 参数（默认 1.0，无来源） | core 抽取层 | 气运/福缘隐藏数值、天才地宝异象事件（EP2） |
| H7 | **势力关系图 + 战争状态机**：`factionId×factionId` 态度矩阵（敌对/中立/同盟，数值化）+ 声明式冲突定义表（参战方/起因谓词/阶段/和谈条件/世界后果），由 H5 调度、H2/H3 结算 | core + tables | 宗门对立、**人妖大战（一次性主线或周期活动两形态同表承载）**、外敌入侵、万族棋局（EP3/EP4） |

约束：H1–H7 只定义**结构与读写入口**，任何"玩法化"（NPC 商人、拍卖会 UI、战争的具体剧本……）都必须按 01 分册新系统立项流程（ADR + 准出条件）另行批准。战争剧本必须写成 H7 的表定义，代码只提供状态机原语——§2.1"变形测试"对此强制适用。

> 键格式口径：H3 的 flag 命名空间用冒号分段（`faction_ch3:war_outcome` 式运行时键，走 Validator flag 引用校验），与内容 ID 的下划线格式（04 §4 资源文件名键）**刻意不同**，评审与工单中不得混写。
