# 《玄黄劫争（Primordial Strife）》项目开发手册

> 版本 v2.0 ｜ 更新日期 2026-10-25 ｜ 状态：生效中
>
> **本手册是项目的唯一参照（上位约束）。** 任何与手册冲突的文档、聊天记录、代码注释一律以手册为准；修改手册必须走 ADR 流程（见第 08 章）。
>
> **手册 vs 实况的分工**：手册写"应该怎样"（规范、准出条件、契约），[`10-当前进展与交接.md`](10-当前进展与交接.md) 写"现在怎样"（已完成/遗留/下一步）。二者冲突时**先信手册的规范条款**，再按 10 册的遗留台账排期修；**不允许用"手册没写"来否认代码里的既成事实**，也不允许用代码现状反向改写规范。

## 这是不是一个"文档很多"的项目？

不是。全套规范 11 个分册 + 4 份真相源 + 5 份历史附录。**日常开工只读三份**：本页（地图）、[10 当前进展](10-当前进展与交接.md)（实况）、[07 开发路线](07-开发路线与迭代计划.md)（排期与准出）。其余按需查阅。

## 开发模式（ADR-024）

项目由**本人独立开发 + AI Agent 执行**：本人是唯一决策者、实现者、审核者、真相源确认人与发布负责人；Agent 产出默认"未验收"，不得自批、不得代确认真相源、不得改门禁。06 分册的权限分区保留，但解释为**对 Agent 的限制**，不再对应人员角色。历史文档中的 A/B/C/D 与"通道 A/B/C"是已废止的旧称谓，分别统一理解为**本人**与**通道 1/2/3**。

单人复核由四道防线替代：红先测试、全新上下文只读复核、外部门禁、本人实机证据（07 §8.3）。

## 快速上手

### 本人

1. 读 01（10 分钟）→ 10（实况）→ 07 §4.1（当前 P0 批次）。
2. 按 02 分册搭环境；Windows 中文路径下用通道 2（ASCII worktree）跑单测。
3. 每批只取 07 §4.1 中的一条任务；验收命令与证据路径先写清。
4. 交单前跑 `./gradlew spotlessCheck build test validator`（06 §4），全绿并附输出。

### 新会话 Agent

1. 读 `AGENTS.md` + 06 §2（权限分区）与 06 §4（验收链）。
2. 读 10（实况）与 07 §4.1（本阶段范围），确认任务落在开区或授权灰区。
3. 按 06 §3 的任务模板接收边界、验收命令、证据与交付物。
4. **不得自批、不得代确认真相源、不得改门禁、不得自行启动游戏**；产出默认"未验收"。

### 内容工作（本人或 Agent 代拟）

先读 [tables/FILLING_GUIDE.md](../tables/FILLING_GUIDE.md)——它把字段契约翻译成人话，§0 说明"现在填表能走多远"（21 张表已接生成器，产物→jar 的通道已接通）。改数值去 `content/NUMBERS.md`，改设定去 `content/LORE.md`，改剧情去 `content/STORY.md`。逐系统的玩法施工说明在 [附录 EP0 功能设计草案](appendix/EP0功能设计草案.md)（历史草案）。
