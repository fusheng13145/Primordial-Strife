### 执行环境观察（待复现验证）
- 带 `Sandbox bypassed (escalation-approved)` 标记的命令，**可见输出可能来自第二次执行的幂等结果**，而真实效果已由第一次执行完成。两条同签名实例：① `git branch -d` 报 `error: branch ... not found`，但引用确实已消失；② `git add + git commit` 报 `nothing to commit, working tree clean`，但提交 `a3e12e8` 已实际创建。
- **判读准则**：提权命令的输出若与副作用矛盾，**以仓库实际状态为准**，不要据「not found / nothing to commit」推断"没发生过"。
- 普通（非提权）路径下探针显示命令只执行一次、输出正常。故此为提权路径相关行为，**尚需更多样本确认**，暂不改写长期经验。
