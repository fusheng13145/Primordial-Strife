## 开发模式与决策权（D2 / ADR-024）

**本人独立开发 + AI Agent 执行。** 本人是唯一决策者、实现者、审核者、真相源确认人与发布负责人。Agent 产出默认"未验收"：不得自批、不得代确认真相源、不得改门禁、不得自行启动游戏。06 分册权限分区是**对 Agent 的限制**，不对应人员角色。

单人复核由四道防线替代：**红先测试 → 全新上下文只读复核 → 外部门禁（CI/Validator）→ 本人实机证据**（07 §8.3）。

## 术语与口径契约

**统一规则**

1. **一义一词**：上表未列的自造同义词视为口径违规；`qi` 只指修为，环境量必须写全 `ambient_qi`，货币只有灵石。
2. **编号即锚点**：分册章节号（`05 §4`）、决策号（`D6`）、ADR 号、钩子号、校验规则号（`V-*`）、任务号（`G-*`/`P0-12`）、阶段号（`M*`/`P*`/`EP*`）是跨文档与代码注释的引用锚，**只增不改不删**；重排分册正文时章节编号必须保持稳定。
3. **数值只在真相源**：文档中出现受管数值必须带来源（`NUMBERS @@块` / 表名），不得独立成文以免产生第二真相源。
4. **史料与判据分离**：已废止的 ADR 与旧称谓保留标记（`已废止`/`已被 ADR-0xx 覆盖`），说明压到一行；现行口径只写在正文，不在正文里讨论历史。
5. **结论与猜测分开**：`[拟]` = 待拍板草案，`[占位]` = 未定内容，未实测一律标"未验证"；禁止用未标注的陈述句表达推测。

## 快速上手

**本人**：读 01 → 10 → 07 §4.1（当前批次）；按 02 搭环境，Windows 中文路径下用通道 2 跑单测；每批只取 07 §4.1 一条任务，先写清验收命令与证据路径；交单前跑 `./gradlew spotlessCheck build test validator`（06 §4）并附输出。

**新会话 Agent**：读 `AGENTS.md` + 06 §2（权限分区）与 06 §4（验收链）→ 读 10 与 07 §4.1 确认任务落在开区或已授权灰区 → 按 06 §3 模板接收边界。产出默认未验收。

**内容工作**：先读 [tables/FILLING_GUIDE.md](../tables/FILLING_GUIDE.md)（字段契约的人话版，§0 说明当前填表可走多远：21 张表已接生成器，产物→jar 通道已接通）。改数值去 `content/NUMBERS.md`，改设定去 `content/LORE.md`，改剧情去 `content/STORY.md`。
