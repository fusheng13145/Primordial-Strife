## 核心结论：ID 不能用中文（物理约束，非风格偏好）
用户要求"模组内所有故事/物品命名都用中文"，但准确落点是 **ID 用 ASCII 拼音、玩家可见文本用中文**，理由三条：
1. 原版 `ResourceLocation` 只允许 `[a-z0-9_.]` → **中文 ID 加载期直接崩**（不是警告，是崩）
2. 1.21.1 掉落表路径由注册名唯一推导（`BlockBehaviour` 用 `withPrefix("blocks/")`）→ ID 与掉落表路径是**同一条约束**
3. Java 标识符可含 Unicode 但不可含 `-`；CSV 表头是列契约（改列名=破档）

**中文化审计结果（已达成，无需再动）**：lang 109 条全部含汉字、零空串、zh_cn/en_us key 双向完全对齐；对话正文 41 条全中文；代码内玩家可见文案 20 处全中文。

## 关键设计决策：把文档规范落成机器门禁
docs/11 规范若只写文档会漏，所以新增第 12 项门禁 **V-NAME**（`NameConventions.java`）：
- 查**源表与产物两侧**的 ID 形状（只查一侧会漏：只查产物要等 DataGen 后才发现，只查源表则产物被手改漏）
- 拦中文 ID 并在报错里说清"会崩"而不只是"不合规"
- lang key 三段式；**zh_cn 值必含汉字**，en_us 按 ADR-009 允许占位

### 连带发现并修复的实现缺口（比缺实测更重要）
docs/03 §6 红线写「**新区块灵气场生成 ≤2ms/chunk**，实现手段：**区块生成期**计算」，
但**全仓没有任何区块事件挂钩**——灵气场只在 `StrifeWorld.environmentCoefficient`（玩家查询时）惰性求值。
后果不是"慢"，而是**成本出现在错误的位置**：新区块灵气从未预热，冷启动尖峰落在查询线程。

选 `Load` 而非 `ChunkDataEvent`：后者在区块序列化数据阶段触发，那时区块尚未进入可查询状态。

### 关键判断：性能测试必须用真实噪声
`AmbientQiFieldTest` 那 7 例用假噪声钉行为（对），但**假噪声比 `ImprovedNoise` 快一到两个数量级，拿它报毫秒数是自欺**。
所以 `AmbientQiBenchmarkTest` 是全仓唯一必须用真实 MC 噪声的测试。
断言刻意宽松（红线 10 倍 = 20ms）：CI 机与本机 CPU 差异可达数倍，绑死 2ms 会让门禁随机红；
宽松上限只兜**数量级退化**，真实读数靠 `ambient-qi-bench` 打印行 + 入档。

### 自己踩了两次的坑（都是"测试算错"不是"实现错"）
区域是 `floorDiv(chunk, 16)`：
1. 用"对角线遍历"想一次造冷与热 → `chunk=i*16` 落在第 i 个区域，256 块 = 256 个不同区域，区域内命中那条**根本没走到**
2. 改用 `i/16` 铺开 → 算出 16 次采样实际只有 1 次（`i<256` 时 `i/16` 只有 0..15，`baseX` 固定 → 仍在同一区域）

**结论：区域粒度是 16 时，"同一区域"只能靠 `% 16` 制造，靠 `/ 16` 只会换区域。**
