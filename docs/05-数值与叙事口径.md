# 05 数值与叙事口径

## 1. NUMBERS.md：全部数值的唯一真相源

- 位置 `content/NUMBERS.md`；一个二级标题 + **唯一** ```yaml 围栏块，块以 `@@<id>` 行定位；DataGen 解析失败 = 构建失败，解析契约以 `content/JSON_SCHEMA.md` 为准。
- 收录范围（**代码出现这些字面量即 Review 驳回**，运行期一律查 DataGen 产物）：境界链（qi_max/lifespan/unlocks）、突破/渡劫成功率、打坐基础速率与打断惩罚比例、灵根系数表、成长比校验区间、丹药加成、寿元结算、伤害公式表、冷却/消耗、掉落概率、限速参数。
- 配置口径：config 只放行为开关与性能档位（日志级别、同步频率上限）；凡玩家成长/战斗/经济可感知数值归 NUMBERS 管辖经 DataGen 进表，**禁止做成 config 数值项**形成第二数值真相源。
- 调参流程：改 NUMBERS.md → DataGen + Validator（越界/成长比）→ 蒙特卡洛抽样 → 提交。

## 2. 核心公式（口径锁定）

```
实际修炼速率 = 基础速率(查表) × 灵根系数 × 环境系数(AmbientQi) × 功法倍率 × (1 + 丹药加成)
```

- 基础速率与四项系数全部来自表（`@@realms.sit_rate` / `@@spiritroot` / `@@world` 灵气浓度 / techniques 表 / `@@pills`）；任一系数为 0 必须有可展示的 tooltip 解释（"灵根不适配"）。
- 伤害：`damage = formula_key 查表(base, 境界系数, 功法加成, 穿透)`，禁止公式旁路（`@@combat`）。
- 相邻境界总成长比锁定 **1.8–2.5**（`@@limits`），Validator 硬校验（风险 R3）。

## 3. 境界链（M0 骨架表基线）

链序：凡人 → 练气（1–9 层）→ 筑基（初/中/后/圆满）→ 金丹 → 元婴 → 化神 → [后三段暂定 炼虚 → 合体 → 渡劫/飞升，占位命名，随 STORY.md 定稿]。

- 九境为**境**（`realm.ordinal`），境内分层为**小境界**（`stage`，段数取 `stage_count`，阈值按 `qi_max × i / stage_count` 等分、不入表）。
- 每境必填 qi_max、lifespan、unlocks（功能/内容清单）、breakthrough_success_key。成功率锚点（`@@breakthrough`，NUMBERS.md 定稿前视为草案）：练气→筑基 90%、筑基→金丹 85%、金丹→元婴 75%→70%（失败每次 -5%，下限 40%）。
- **O1 拍板**：骨架表（全链条 + 必填字段 + 锚点值）是 M0 准出物，本人 + Agent 产出、本人审定；此后数值变更只走表格流程，不走聊天。

## 4. 代价结算（O4/D6 已拍板）

**四类事件一律不降境**（`realm.ordinal` 单调不减）、**绝不删角色**；代价只在四项池内组合：**降小境界（降层）1–2 层、`qi` 按比例回退、寿元损耗、随身物损失**。细则入 NUMBERS.md 的 `@@downgrade` 段（**待建**，随 G-5 定稿）。

| 事件 | 代价（`qi` 回退区间、状态键、比例全部查表） |
|---|---|
| 突破失败 | 降层 1–2 层 + `qi` 回退至上限的 60%–80%（`@@breakthrough_cost.qi_reset_ratio_min/max`）+ 本次投入的突破辅助材料损耗；不损寿元、不掉随身物 |
| 渡劫失败 | 突破失败全部代价 + 重伤（全属性 -30%、限时，`@@breakthrough_cost`）+ 天劫材料散落劫台附近可拾回 |
| 寿元尽（大限） | 降层 1–2 层 + `qi` 回退 + 寿元重置为"残余寿元"（该境 `lifespan_years` × `@@lifespan.dasheng_reset_years_ratio`，至少 1 年）+ 虚弱（`@@lifespan.dasheng_debuff_key`）；提供明确的续命玩法路径（丹药/任务） |
| PVP 致死（D13） | 降层 1–2 层 + `qi` 按比例回退 + 随身物损失（死亡掉落规则）；不降境 |

- 已在凡人时退无可退，寿元照旧重置——续命玩法的意义所在，不是把玩家逼进死循环。
- 代价**可感知、可恢复、可预期**：失败后果（回退区间）随视图下发并在面板预告，玩家押注前读得懂。
- 实现口径：`qi` 按比例回退与重伤/虚弱状态已实现；**降层待实现**；大限现行按 `@@lifespan.dasheng_realm_drop_stages` 退**境**档，与 D6 冲突、**待改为降小境界**（未收口）；PVP 致死代价**待实现**（对战规则批次）。

## 5. 修为获取渠道（O3/D7 已拍板）

锁定三渠道：**打坐（主）、丹药（加成）、任务奖励（节点性）**。杀怪与机缘经掉落材料与任务奖励接入，**不构成新渠道**；"悟道"作为剧情奖励走任务系统。灵石购买修为、挂机收益之类一律不做。新增渠道 = 改 NUMBERS 渠道表 + ADR + 面板来源明细同步。

## 6. STORY.md：世界观与章节大纲

- 位置 `content/STORY.md`；结构：世界观总纲 → 各章主题/场景/关键 NPC/情感曲线 → 任务节点骨架（与 quest DAG 表用 `ch<N>_` ID 前缀互引）。**O2 拍板**：序章大纲 M2 末产出、M3 前定稿冻结；第一章允许 M3 期间滚动定稿，但节点骨架先冻结再填对话文本。
- 主题基调：**「玄黄劫争」——万族争劫、大道并立**。世界有自己的大势（宗门对立、人妖之战、外敌入侵等主线级事变），玩家可入宗门、可行散修之道，在事变中择路而非旁观；叙事重心是"个人求道与世界洪流的相互作用"（H2 身份 / H3 因果 / H7 战争钩子即其工程表达）。
- 对战边界：**玩家对战按规则完备级全量落地**（规则面见 01 §9 D13：限伤 / 三态开关 / 红名声望 / 死亡掉落 / 邀约决斗）；反作弊对抗与竞技平衡体系仍不做（01 §5）。势力对抗是模拟出来的世界内容，不是竞技场——对战与宗门关系只是同一批原语的另一组剧本（01 §7），不另建系统。

## 7. AI 文本生产流程（D2）

```
STORY.md 节点骨架 → Agent 起草对话/条目文本（附上下文包：世界观卡 + 前文 + 目标情绪）
→ 本人润色（native zh_cn 语感）→ 入 tables/dialog_trees 与 lang 源表 → DataGen + Validator → 抽查回放
```

- 每节点首版允许骨架文本（2–3 句），玩法优先（风险 R2）；情感关键节点（序章突破、章节首领告别等）必须本人重写。Agent 产文须同时提交文本 + 变体 2 个 + 用到的设定引用清单（防吃书）。
- **一致性防线**：`content/LORE.md`（设定卡，随 STORY.md 维护）是所有 Agent 文本任务的强制上下文输入；与 LORE 冲突的文本在本人审核阶段驳回。
- **版权红线**：09 分册与调研报告中的网文专名（"韩立式""荒古圣体"等）与情节**仅限内部调研用语，一律不得进入游戏内文本/资产命名**；对外内容须为自研设定（LORE.md 卡内），本人审核含"致敬相似性自检"一项。

## 8. 本地化节奏（O5/D4 已拍板）

zh_cn 为源语言，key 全覆盖是硬门禁；en_us 在 M5 前由 Agent 批量翻译占位过 CI（允许机翻低优先级），M5 起随平衡迭代逐章精修，Beta 前完成序章 + 第一章。

## 9. 动画与表现范围（O6/D5 已拍板）

M2 战斗表现 = 原版弹道 + 粒子 + 音效（AI 生成短音效）。GeckoLib 至多用于 1–2 个高规格 Boss/妖兽，接入与否由本人在 M4 末评审；`AnimationProvider` 保证"无动画也完全可玩"。

## 10. 联机优先级（O7/D3 已拍板）

单人优先。服务端权威 + 幂等 + 限速从 M0 就按 03 分册执行（这是架构，不是功能）；**多人功能加固（同屏性能、多人任务协作、反滥用调优）与玩家对战规则同排在 M5 批次**（M0–M4 不做，D13）；Beta 明确标注"联机为实验性"。
