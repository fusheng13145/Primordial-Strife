### 关键结论：1.21.1 方块掉落表路径由注册名唯一推导
- 1.21.1 **无** `LootableBlock`；`Properties` **无公开** lootTable setter；`Block.getLootTable()` 是 **final**
- 路径 = `BuiltInRegistries.BLOCK.getKey(block).withPrefix("blocks/")`
- 故 `drop_table` **必须**为 `blocks/<方块ID>`，否则**矿挖了掉空气且不报错**（静默断链）
- 这是本项目"运行时自检命令 `/strife world ore status`"存在的根本原因

### 关键结论：1.21.1 `BuiltInRegistries` 无 `BIOME` 字段
群系是动态注册表，只能 `server.registryAccess().registryOrThrow(Registries.BIOME)` 访问（需已起服）。
→ 分层纪律：`OreTables` 只校验群系 ID **形状**（可纯单测），"ID 是否真实存在"移交 `OreCommand` 运行时核对。

### 工具使用教训（本机 Windows + Git Bash）
- `gradle -q` 会把 `datagen:` / `validator:` 统计行**吞掉**——要拿口径就别加 `-q`
- `grep ... | head -N` 会被满屏 `UP-TO-DATE` 占满导致**看不到末尾 BUILD 行**——用 `tail -N`
- 主工作树中文路径下 `gradle test` 报 `ModLoadingException: Failed to find net/minecraft/server/MinecraftServer.class`（与早前的 `ClassNotFoundException` 同源，GBK + 非 ASCII 路径缺陷 gradle#30304/#30391）。**换路径不换代码**：`git worktree add C:/strife-test <commit>` → `cd C:/strife-test/mod && gradle --offline cleanTest test`
- 只改文档的提交会让 `test` 报 `UP-TO-DATE`（测试输入未变）——此时用 `cleanTest test` 强制重跑，再从 `build/test-results/test/*.xml` 汇总真实用例数，别把 UP-TO-DATE 当成"跑过了"
- `C:/strife-test` worktree 测完要 `git worktree remove C:/strife-test --force` + `git worktree prune`
